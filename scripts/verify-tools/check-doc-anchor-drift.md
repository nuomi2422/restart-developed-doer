# check-doc-anchor-drift · 查文档里的代码锚点有没有漂

> **干什么**：扫文档里所有 `Foo.java:123` 和「N 行」体量锚点，跟真实源码比对，
> **给出新行号**，让人/AI 把文档改对。
>
> **为什么需要**：`30-主要功能不回退清单.md` 自己写了「数字引用规约」——
> 任何「N 项测试 / N 处引用」必须带模块拆分 + 日期 + 查证路径。
> 但那是**纪律不是机制**，所以照样漂。2026-10-01 实测：
> `RddPlugin.java` 从文档写的 623/1150 行漂到实际 1554 行，`RddPlugin.java:69`
> 实际在第 70 行，`RddStallWatcher` 165→311 行。**没人发现，因为没有任何东西会报警。**

## 怎么调

```powershell
# 基本用法（退出码有意义，能当证据用）
node .\check-doc-anchor-drift.js --docs "E:\新建文件夹\rdd-docs\rdd架构\自编译统一版" `
                                  --src  "E:\restart developing doer\minecraft-numen"

# 多个文档目录一起查
node .\check-doc-anchor-drift.js --docs "<目录A>" --docs "<目录B>" --src "<源码根>"

# 容差调到 5 行（更严）
node .\check-doc-anchor-drift.js --docs "<目录>" --src "<源码根>" --slack 5

# 逐条打印对得上的（调试用）
node .\check-doc-anchor-drift.js --docs "<目录>" --src "<源码根>" --verbose
```

| 参数 | 默认 | 说明 |
|---|---|---|
| `--docs` | 必填，可重复 | 含 `.md` 的目录，递归 |
| `--src` | 必填 | java 源码根，按**文件名**定位 `.java` |
| `--slack` | 15 | 「行号大致算对」的行数容差 |
| `--verbose` | off | 连 CLEAN 的锚点一起打 |

**退出码**：`0` = 无确定漂移 ｜ `2` = 有确定漂移 ｜ `3` = 用法或环境错。
符合 `verify-tools/README.md` 第 5 条，可以直接接 `run-mutation.ps1 -CollectEvidence` 当证据。

## 判定分七档（故意不谎报）

| 档 | 含义 | 怎么处理 |
|---|---|---|
| **DRIFT** | 符号还在，只是行号偏了 | **报告直接给了新行号**，照着改文档即可 |
| **SIZE_DRIFT** | 类行数偏了 | 同上，报告给了实测行数 |
| **DEAD** | 文档说的符号在代码里**彻底没了** | 不是漂，是失效——要么代码被改名，要么那段被删了，得查历史 |
| **MISSING_FILE** | 引用的文件在源码树里不存在 | 多半是拼错，报告会提示形近的真名 |
| **UNVERIFIABLE** | 文档只写了行号、没写符号 | **不判死**，把该行实测内容打出来，人/AI 一眼判 |
| **HISTORICAL** | 上面任一项出现在**带日期的历史快照**里 | **不算今天的债**，单独列出 —— 见下 |
| CLEAN | 对得上 | 只在 `--verbose` 时打 |

### 为什么要有 HISTORICAL 这一档（这是最重要的一条设计）

像 `23-A组架构四件套合入-20260928.md`、`测试日志.md`、`09-更新日志.md` 这种，
它记的是**当时**的代码长什么样 —— 写它的那天，`RddPlugin.java:81` 确实是 `MAX_REPLAN_PER_PRIMARY`。

**把它当漂移去"修"就是篡改历史记录。** 所以工具按文件名自动分流：
带 `-YYYYMMDD` 后缀，或名字里含「测试日志/更新日志/纪要/记录/检测报告/快照」的，
一律归 HISTORICAL，只报数量不报细节。

**判据故意保守**：宁可漏判成 HISTORICAL，也不把活文档误判成历史。
只有活文档（README / 30 红线 / 24 运维 / 50 / 51）的偏移才是**今天该还的债**。

> 实测效果：改造前 40 处「漂移」，分流后**活文档只剩 8 处**，
> 36 处归档到历史快照。噪音去哪了？——**没消失，只是归位了**。

### 工具踩过的坑（都写在这，免得后人重踩）

1. **第一版没分档 → 40 处里几乎全是假警报。** 判定逻辑要求「类名出现在锚点行附近」，
   但 `RddPlugin.java:69` 指的是类体内部的字段、类名当然不在那一行。
   **教训：判定必须能给出理由，不能只给结论。**
2. **`stripMd` 吃掉下划线 → 一律误报 DEAD。** 文档里 `` `MAX_REPLAN_PER_PRIMARY` ``
   被剥成 `MAXREPLANPERPRIMARY`，源码里永远搜不到。
   修法：对「全大写驼峰」生成带 `_?` 的宽松模式逐字符对齐。修完 DEAD 归零。
3. **递归扫到嵌套目录会重复报告**（子目录 + 父目录都扫了）。
   修法：只扫顶层 + 一层子目录，并用 md 绝对路径去重。
4. **`is_dark_outside` 这种字符串字面量不是声明**，不能拿它当符号查。
   宁可标 UNVERIFIABLE 附实测行内容，也不要判死。
5. **多锚点行符号归属串了**（`A.java:16 B.java:16 C` 里的 C 被归给了 A、B）→
   误报 DEAD+DRIFT，**我据此把一份完全正确的文档改坏了**。
   改成逐锚点按位置配对 + 裸类名降级不参与行号判定。
   **教训：「修出来的错」比「不修」更贵。**
6. **★ 拿文件名猜「历史快照」→ 漏了 19 份。** 第一版只按文件名（是否含日期/日志字样）
   判定哪些是历史快照，结果 `RDD-红线健康度-20260927.md`、`ac-module-verification.md`、
   `进游戏巡检规范与异常记录.md` 等 19 份明明是历史快照，却被当成活文档的真债，
   白报了一堆。**改为按文档内容（前 12 行有日期 + 「快照/当时/实测」措辞）判定。**
   效果：确定漂移从 21 → **0**，113 处正确归入历史快照。
   **教训：这是第 5 条的同一个病 —— 拿猜测当事实。判据必须是能验证的东西。**

## ⚠️ 三条铁律（这工具教给我的）

1. **工具报「有问题」≠ 文档错了。** 改之前先人工核实一次 ——
   而工具报错恰好会让人以为「已经核实过了」。
2. **历史记录里的偏移是正常的**，不是债。改了就是篡改历史。
3. **判据不能靠命名/文件名这类猜测**，必须能验证（内容、运行时事实）。

## 🔴 已知缺陷（2026-10-01 实测，尚未修）

**符号归属模块不可靠 —— DEAD / DRIFT 这两档在多锚点行上会误报，不要拿它的结论改文档。**

**怎么撞上的**：有一行文档长这样（`numen-mcp-机制-源码核对版.md:48`）

```
| 交互 | `interact_at` … | `InteractAtTool.java:25` `InteractEntityTool.java:25` `GuiOps` |
```

三个类名挤一行，两个带行号锚点、一个裸引用。工具把 `InteractEntityTool`
这个符号拿去 **`InteractAtTool.java` 里**找 → 找不到 → 报 DEAD + DRIFT。

**我据此改了文档**：把本来完全正确的 `:25` 改成 `:16`。**改错了。**
人工核实：`InteractAtTool.java:25` 和 `InteractEntityTool.java:25` **都是对的**
（就是 `return "interact_at";` / `return "interact_entity";` 那两行）。已还原。

**根因**（未修）：符号归属靠「正则抓这一行的反引号内容」，没有做**位置切分**。
一行里有多个 `.java:N` 时，应该按锚点位置把文本切开，每个锚点只认自己区间里的符号。
我改了两版都没修对 —— 说明这个模块**不该继续打补丁，该重写**。

**所以现在怎么用这个工具**：

| 档位 | 可信度 | 能不能拿它改文档 |
|---|---|---|
| **SIZE_DRIFT**（类行数） | ✅ 高 | 可以 —— 独立解析，不依赖符号归属 |
| **MISSING_FILE** | ✅ 高 | 可以 —— 只查文件名存在性 |
| **HISTORICAL** 分流 | ✅ 高 | 可以 —— 按文件名判定，不碰符号 |
| **DRIFT** | ⚠️ 单锚点行可信，多锚点行不可信 | **先人工核实那一行** |
| **DEAD** | ⚠️ 同上 | **不要直接照改** |
| **UNVERIFIABLE** | ✅ 高（本就不判死） | 它已经附了实测内容，照着看就行 |

**判据**：`grep -c "\.java:" 那一行` > 1 → 多锚点行 → DRIFT/DEAD 一律先人工核。

> **教训（比这个 bug 更值钱）**：
> 「检测工具报了问题」≠「文档错了」。我这次差点把一份**完全正确的文档**改坏。
> **改之前必须人工核实一次** —— 而工具报错恰好让人以为「已经核实过了」。
>
> 更好的做法：**工具应该输出「疑似」而不是「确定」，并且不该诱导人去改历史记录。**

## 依赖什么

- Node.js（无外部依赖，纯 `fs`/`path`）
- 源码侧：不需要编译，读文本即可
- 不写任何文件，只读 → 可以随时安全重跑

## 什么时候该删

被 `loop-gate.js` 正式接管、且规则稳定半年后，可以降级成 `loop-gate` 的一个内部模块。
在那之前它独立存在，方便单独调、手动看。

## 建议接到哪里

1. **`loop-gate.js` 加一项**：每轮收尾跑一次，`VERDICT=DRIFT` 就要求「要么修文档、要么修代码、
   要么在文档里写明『此行号已重写，见 XXX』」，不允许沉默。
2. **`stager` 收口阶段**：`stager close` 前跑一次，把报告写进 `evidence` 文档。
3. **不要**接进 `run-mutation.ps1` 的编译链——它跟编译无关，是文档一致性检查，
   放在收口更合适。

## 已知的坑

- **只认行号锚点和体量锚点**。文档里「类 X 负责 Y」这种没有位置信息的描述查不了，
  那是**结构漂移**，本工具管不着（要治得靠另一类工具：反向生成类职责表）。
- **同名文件**（不同包下都有 `Memo.java`）会逐个候选都试，取最贴近的。
  理论上会误判，但比漏判好。
- **`bodySubmissionEnabled` 这类在表格单元格里被 `|` 隔开的锚点**能查到，
  但表格里若同行提到两个 java 类，体量锚点会跳过不判（避免张冠李戴）。
