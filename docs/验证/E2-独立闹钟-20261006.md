## 2. 设计要点

### 2.1 为什么不是往串行链里塞规则

旧 `CarrierChain.evaluate` 是**分级短路**链（第 i 级不成立 → fix + break，后续级根本不求值）；且 `CarrierRuleStore.effective()` 把已批准规则整体插在默认链之前——任一条不成立会短路掉整条默认链。低血条件不成立就会压掉饥饿/夜间/苦力怕告警。因此：

- 旧 `<carry>` 串行链**原样保留**（兼容入口，语义与既有测试不动）；
- 新增 `CarrierAlarms`：每条闹钟**独立求值、无短路**，`evaluate()` 返回全部命中；
- 两条通道各自独立判空，互不压制；单条闹钟求值抛异常 → 产出 `rule-error` 命中（不静默）。

### 2.2 四条闹钟（v1）

| rule | 触发 | 分级 | 文案要点 |
|---|---|---|---|
| `hungry` | food ≤ 6 | 有食物/没有食物/未知 三档建议 | 有食物=吃；没有=先弄食物；未知=先看背包 |
| `low_hp` | hp ≤ 10（≤4 升 P0） | 状态而非无条件吃饭指令 | 回血/避险建议；已饱也提醒（低血≠饿） |
| `night` | `night=1` | 敌对优先 / 有床可睡 / 无床撑过 / 床未知 | 只在有昼夜维度出现（下界/末地不触发） |
| `creeper` | 点燃或 ≤4 格（P0）；否则 P1 | 距离分级 | 缺失键=不触发（脱离即恢复） |

常量：`HUNGRY_LEVEL=6`、`LOW_HP=10`、`CRITICAL_HP=4`、`CREEPER_CLOSE=4`。

### 2.3 采样契约扩展（两处快照生产端同步）

新键：`bed=<床个数>`（BedItem 语义，-1 未知）、`time=<dayTime%24000>`、`night=1/0`（**仅非 fixedTime 维度写**）、`creeper=<最近距离>` + `ignited=true/false`（**仅范围内有苦力怕才写**）。不存在的字段缺键，不猜默认值。

### 2.4 通道与可观测

- `<alarms scope="nearby16">` 追加进 `<rdd>`（与 `<carry>` 同一条 runtime_state 被动通道，每轮现算不入历史）；
- 新 `carrier_alarm` 事件（`added`/`escalated`/`removed`/`active`），**只在状态变化时**发（RddMonitor → rdd.jsonl）；
- **E2.2 主动唤醒**（第二批）：危险边沿（`wakeWorthy` = added/escalated 且 P0 且规则 ∈ {creeper, low_hp}）→ `CompanionAlerts.danger()` → `NumenEvents.alarm()`（Kind `ALARM`，**urgent=true**）→ 主人在线走 NumenEventPayload，客户端 `pushEvent` 进队列并在下一个可插入时机立刻送达（LLM 忙时排队，不丢）；night/hungry/active 边沿不叫（饥饿已有 `gotHungry` urgent 通道，不重复）。
- 唤醒限频：每同伴每规则 30s（`WAKE_COOLDOWN_MS`，只管通知、不限求值）；同伴死亡时不叫；`woke` 计数写进 `carrier_alarm` 事件。

## 4. 缺口与后续（诚实边界）

1. **主动唤醒只做了「送达」**（E2.2）：没有做**确定性生存反射**（不等远程 LLM 的自动撤离/拉开距离）——LLM 忙时急件排到下一个可插入时机，仍可能晚；唤醒本身花一轮模型调用（execution 角色，受 budget enforce 约束，预算拦时事件排队等窗口，不静默丢）。
2. **「被执行者采纳 → 世界结果」长线归因未做**：E2.2 烟测有「收到→开 attack 任务」的时序证据，但无对照组（ACX 当时也在续跑遗留目标），严格归因需长线观察。
3. **DSL 未扩词**：`CarrierRuleStore` 白名单仍只有 hp/food/food_items，自定义规则暂时用不上 night/creeper/bed 键。
4. **modded 床**：`bedCount` 按 `BedItem` 判定，非 BedItem 子类的模组床会漏计（bed=0 可能不准）。
5. `RddCarryHint.render` 仍无单测（本轮只覆盖 CarrierAlarms 与接线顺序 pin）。
6. 「已完成」引擎侧气泡（E0 顺延）与按任务聚合/排队时间仍未做（E0 §5）。
