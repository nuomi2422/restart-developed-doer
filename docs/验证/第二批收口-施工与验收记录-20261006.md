### 2.2 ✅ P0-B：提醒「先记账、后发送」——发了没发都算拍过

**位置**：`plugins/rdd/.../RddStallWatcher.java`（5 处）+ `plugins/rdd/.../RddPlugin.java`

**原缺陷（读源码确认）**：

```java
if (条件 && !alreadyNudgedFor(uuid, "idle", stateKey)) {
    markNudgedFor(uuid, "idle", stateKey);      // ← 先记账
    ...
    RddPlugin.nudge(uuid, "...");               // ← 后发送（可能返回 false）
}
```

而 `RddPlugin.nudge` 在三种情况下返回 `false`：监督暂停 / 3 分钟总闸 / 参数无效。

⇒ **一次都没发出去，却把那个状态永久判成「已提醒」**。
⇒ 实测形态（`monitor/rdd.jsonl` 10-05）：`nudge_throttled` **15** 次 vs `supervisor_output` **9** 次 ——
六成提醒被自己的记账顺序吃掉；且被判据（10 秒）判出的状态就此**永久沉默**。

**修法**：

- `RddPlugin` 新增**只读**的总闸查询 `nudgeAllowed(uuid)` + 单一来源的 `msSinceLastNudge(uuid)`；
  `nudge()` 内部也改用它（不再两处各写一遍比较）。
- `RddStallWatcher` 新增 `nudgeOnce(uuid, kind, stateKey, message)`：
  **去重命中 → 不做；闸没放行 → 不发也不记账（下周期自然重试）；发送成功 → 才记账**。
- 5 个调用点全部改走 `nudgeOnce`：`idle` / `dead` / `escalate` / `stall` / `renudge`（+ `stalled_entry`）。
- 监测事件 `llm_idle_stall` / `dead_task_stall` **只在真的发出去之后才记** ——
  否则闸没放行时它会每个检查周期重发一遍（另一种刷屏）。

**为什么不直接把 `markNudgedFor` 删掉**：`track()` 每周期都跑，去掉记账会在总闸窗口内
**每周期调一次 `nudge`**，把 `nudge_throttled` 刷成周期一条。所以必须是「先问闸」。

**⛔ 我没有做的事（重要）**：

- **没有把 `MIN_NUDGE_INTERVAL_MS`（180 秒）改小。**
  改阈值是**产品决定**，而且原注释解释了 180 秒的来历（10-03 实测 42 次刷屏全是钱）。
  本轮只修「记账顺序」这个**确定的接线错误**；间隔该不该降，等实机数据。
- **没有恢复精确坐标作为进展判据。** 现有 8 格粗桶是为治「原地横跳被当成有进展」，
  修提醒不能把这个旧病带回来。

### 11.4 ★★ 过程中撞出的两个**真问题**（都是我自己第一版写错的）

**① `turnPause = BLOCKED` 是粘性的 ⇒ 我的冷却期形同虚设**

第一版我给这条也设了 `turnPause = BLOCKED`（照抄「没 key」那条）。实测发现**门禁只打了一次就再没动静**。
根因：`AgentTurnPause.afterWakeEvent()` 只清 `RECOVERABLE_FAILURE`，`BLOCKED` 要等主人 abort 才清；
而 `tryStartTurn()` 在**我这条检查之前**就有 `if (turnPause.isPaused()) return false;`
⇒ 设了它，之后永远到不了我这条检查 ⇒ **从「熔断」变成「永久锁死」，会把只是偶尔拒收的同伴按死**。
修法：这条**不设 turnPause**（让每个唤醒事件都零成本地重查一次），配合冷却期自动放行。

**② 整个 `ModLanguageData` 目录在运行时是死的（既有问题，不是本轮引入）**

实测聊天栏显示的是**原始 key** `numen.endpoint.rejecting`。查下去发现：
**8 个 numen jar 逐个检查，全都没有 `assets/*/lang/*.json`** ——
`ModLanguageData` 是 **datagen 的源**，而生成的 lang JSON 从未产出/未随 jar 发布。
⇒ **所有 `I18n.get(Keys.*)` 在运行时都返回 key 本身**（此前聊天里那句中文是**硬编码字符串**，不是 i18n）。
本轮处理：我的那条消息**解析不出来就补明文**（datagen 修好后译文自动生效），
并把「lang JSON 缺失」记为**独立的既有债**（不在本轮范围，见下）。

   注意：它**自己说对了要做的事**（放下工作台），但**那一轮之后的所有回合都被 400 吃掉了**，
   所以「它会不会真的去做」**没有机会被验证**。
