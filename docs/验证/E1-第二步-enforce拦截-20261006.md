## 2. 设计要点

- **拦截是纯求值**：`checkBlock(phase, estimate)` 只读配置与窗口，无冷却无副作用——调用点可在每个唤醒事件零成本重查；事件/聊天栏通知的限频单独由 `notifyBlock`（复用 `adviceCooldownMinutes`）负责。
- **两模式事件区分**：shadow → `budget_advice`（建议）；enforce → `budget_block`（拦截），enforce 下不再发建议。
- **三处拦截行为（绝不静默停）**：

  | 角色 | 拦截动作 | 明确出口 |
  |---|---|---|
  | execution | 不开下一轮（不设 turnPause，防粘死锁死） | 状态行/气泡「预算用尽（execution），等窗口重置」+ 聊天栏 + `budget_block` 事件；主人说话/窗口重置/唤醒事件自动重查 |
  | planning | 回落 `RddChainFactory.fromObjective` 占位链 | `budget_block` 事件 + RDD 日志 |
  | learning | `ReviewOutcome.fail` → 队列条目 restore | `budget_block` 事件 + 学习者日志；下一轮重查预算 |

- **安全边界**：一轮收尾的目标判定调用（goal_judging）与已发出的重试**不拦**（最后一轮成果必须判完，沿用引擎既有原则）；`0 = 不限`的角色永不拦截；`checkBlock` 自身异常 → warn 并放行本次（观测/策略永不影响请求正确性）。
- **不做的事**：不自动换 provider；不改并行窗口 provider 文件；确定性生存反射（不等远程 LLM）属 E2，不在此机制内。
