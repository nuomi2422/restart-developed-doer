## 1. 职责与分工

E1 验收要求「相同日志夹具比较 tokens / 重试 / **消息合法性**」。两个夹具各管一半，都是纯离线、不需要游戏在跑：

| 工具 | 管什么 | 数据源 |
|---|---|---|
| `econ-report.js` | 「钱」：tokens 四元/耗时/重试/截断；工具 call↔result 配对耗时；预算建议与拦截 | monitor 各 jsonl 的 `llm_usage` / `budget_advice` / `budget_block` / `tools` |
| `replay-check.js`（本文） | 「正确性」：消息序列合法性（2026-10-06 上午 400 的根因类） | 各 jsonl 的 `llm_request` 事件里**真实发给服务商的 wire body** |

关键事实：`llm_request` 事件的 `data.request` 就是完整请求体（`model` / `messages` / `tools` / `stream` 等），messages 是标准 OpenAI wire 格式（`role` / `content` / `tool_calls` / `tool_call_id`）——所以能对历史请求做「事后验尸」，不依赖复现。

## 2. 用法

```powershell
node rdd-selfcompile\scripts\verify-tools\replay-check.js                      # 默认 live 监控目录，全部历史
node rdd-selfcompile\scripts\verify-tools\replay-check.js --since 2026-10-06   # 只从某天(本地时区)起
node rdd-selfcompile\scripts\verify-tools\replay-check.js --file "D:\rdd\mc\The Best of Twilight Forest\config\numen\monitor\context-1791259005120.jsonl"   # 轮转历史文件
node rdd-selfcompile\scripts\verify-tools\replay-check.js --limit 50 --json    # 样本数 / 完整 JSON
node rdd-selfcompile\scripts\verify-tools\replay-check.js --selftest           # 合成样本自测
```

退出码：`0` 全部合法 / `1` 有违规 / `3` 环境错（目录不存在）。

> ⚠️ `--json` 的消费方用 **node**。PS 5.1 的 `ConvertFrom-Json` 读含中文的 UTF-8 JSON 会报「无效的 JSON 字符串」（GBK 解码拆坏引号），别在 PowerShell 里解析它。

## 3. 校验项（8 类）

| 类型 | 含义 |
|---|---|
| `orphan_tool_call` | assistant.tool_calls 里的 id 没有对应的后续 tool 应答 |
| `orphan_tool_result` | tool 消息的 tool_call_id 找不到来源（典型：压缩后窗口以 tool 开头，assistant 被切掉） |
| `duplicate_tool_call_id` | 同一 assistant 消息里 tool_call id 重复 |
| `malformed_tool_call` | tool_call 缺 id 或缺 function.name |
| `missing_tool_call_id` | tool 消息没有 tool_call_id |
| `empty_messages` | messages 为空 |
| `first_not_system` | 第一条不是 system |
| `empty_assistant` | assistant 既无 content 也无 tool_calls |

## 4. 自测（`--selftest`，7/7 全过）

## 6. 边界（诚实）

- 只校验**消息序列合法性**，不判模型输出质量、工具选择合理性、世界结果。
- 只覆盖被观测到的请求（`llm_request` 事件）；没发出去的请求不在这里。
- 修复前的 400 请求只有部分留在轮转文件里（16MB 轮转，保留份数有限）。
- 违规计数按「请求」聚合；同一次重试的多次尝试各算各的（attempt 语义）。
