# 支线决策 执行/推迟/跳过 —— 实机验证（2026-10-18）

> 续 `世界观测V1-实机验证-20261018.md`。那份里"支线决策因梯子过期未能实机验证"的一节，**本文件予以完成**。
> 实例 live（companion **ACX**）。梯子恢复后重编部署了 `plugins:rdd`（mods 里 rdd jar 更新为 2026-10-18 14:05）。
> 证据源：`D:\rdd\mc\The Best of Twilight Forest\config\numen\monitor\rdd.jsonl`。

## 一、三个决策逐条实机命中

| 决策 | 条件 | 实机回执（原文节选） |
|---|---|---|
| **执行 EXECUTE** | 夜里 + 身体空闲 | `side_task_created` / `side_task_activated` `typeId=sleep, instanceId=sleep-11-…, generation=11, gameDay=0`（重置后再现 `sleep-1, generation=1, gameDay=0`） |
| **跳过本次 SKIP** | 主线目标要"保持夜晚" | `side_task_skipped_occurrence` `typeId=sleep, gameDay=2, reason="mainline_keeps_night:保持夜晚"` —— **只 skip，不 created** |
| **推迟 DEFER** | 夜里 + 身体被占用 | `side_task_deferred` `typeId=sleep, gameDay=4, reason="mid_operation", retryTicks=100` —— **每 ~5s 复现一次，不 created** |
| **推迟→执行** | 身体空出来后 | `task_stop` 释放身体后下一拍：`side_task_created` / `side_task_activated` `instanceId=sleep-4, generation=4, gameDay=4` |

DEFER 的连续三条（06:37:06 / :11 / :16，间隔 5s）正好等于 `BUSY_RETRY_TICKS=100 tick`，
证明「推迟到安全停顿点」不是一次性丢弃，而是**按冷却反复重评估**，直到身体空出才执行。

## 二、没能实机命中的一小格

- **inCombat → DEFER**：只做了离线单测。原因是 ACX 处于 **创造模式**，原版里创造玩家免疫普通怪物攻击，
  没法稳定制造 `hurtTime>0`。这条规则逻辑与 mid_operation 同一条 `decide`，只差事实来源，风险低。

## 三、怎么把它驱动出来的（可复用）

| 目的 | 命令 |
|---|---|
| 设夜（进入睡眠窗口 dayTime∈[11800,23000)） | `node mc-openclaw-controller\scripts\oc-send.js --cmd "/time set 13000"` |
| 推进一个游戏日（换新的去重日） | `... --cmd "/time add 24000"` |
| **取消当前支线**（换目标即作废） | `node rdd-selfcompile\scripts\mcp-call.js rdd_submit ACX @goal.json`（bind 会触发 `mainline goal replaced`） |
| 让身体持续被占用 | `mcp-call.js follow ACX`（**standing 任务，没有终点**，是稳定制造 bodyBusy 的正解；`goto` 会被主线顶掉、反复变空闲） |
| 释放身体 | `mcp-call.js task_stop ACX` |

踩到的坑：
- **`send-mc-command.ps1` 发 `/命令` 没生效**（日志里没有 issued server command）；改用
  **`oc-send.js --cmd "/命令"`** 立即可靠。
- **`/time` 改动不跨强杀持久**：`/time set day` + `/save-all` 后再强杀重启，`dayTime` 仍是旧值
  （`day_time` 回读 13000）。所以"想重启进白天避开自动触发"这条路走不通；正解是**不重启**，
  用 `rdd_submit` 换目标取消支线 + `/time add` 推进日。
- `rdd_submit` 有时回 `invalid RDD task chain: current subtask cannot start`——换个不同的
  `asset_key`/目标文本重提即可成功。
- 清理时 `Stop-Process` 按 **端口属主**（8765 游戏 / 8080 openclaw）杀，别 `Get-Process java` 一把梭
  ——本轮一次 `kill all java` 多杀了 3 个 java 进程（可能含 WineFox 桌宠的 soul-core-bridge），已注意。

## 四、结论

支线"执行/推迟/跳过本次"三个决策**在实机上全部命中**，且与设计文档一致：
跳过≠完成≠永久关闭（下一游戏日重新判断）；推迟按冷却重评估、身体空出即执行；不覆盖正在跑的身体任务。
