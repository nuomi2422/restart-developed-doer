# 世界观测 V1 实机验证记录（2026-10-18）

> 目的：把 `world_state` 从"离线测试通过"推进到"实机验收"。
> 实例 live（companion **ACX**，创造模式，位置 ≈ (10819,76,2194) overworld）。驱动：`rdd-selfcompile\scripts\mcp-call.js`。

## 一、实机跑通的（逐条附原始回执）

| # | 验证项 | 结果 |
|---|---|---|
| 1 | 工具注册 | `world_state` 可被 MCP 调起并回执（未注册工具不会有 JSON 响应） |
| 2 | 环境采集 | `refresh topic=environment` → `SUCCESS / COMPLETE / source=environment`，`day_time=1000, weather=clear` |
| 3 | 读不扫描 + 新鲜度 | `read topic=environment` → `present:true, freshness:STALE, age_ms:30488, coverage:COMPLETE`（>30s TTL 正确判 STALE） |
| 4 | 有界实体计数 | `refresh topic=entities`（绕 ACX 的 30×30×20 盒）→ `count:2, scanned_columns:900, skipped_columns:0, COMPLETE` |
| 5 | 读已有实体观测 | `read`（同盒）→ `present:true, coverage:COMPLETE, count:2` |
| 6 | **读未采集范围 = 明确没有** | `read`（0,64,0..29,83,29 从没刷过）→ `present:false, freshness:UNKNOWN`，**没有偷偷扫描** |
| 7 | **预算明确拒绝** | `refresh` 64000 格盒 → `success:false, reason:BUDGET_EXCEEDED`（64000 > 32768，请缩小范围） |
| 8 | 落盘（按世界隔离） | `config/numen/worldstate/observations.json`：`worldId:"live"` + 环境/实体两条，`revision` 单调（1、3） |
| 9 | 监测事件 | `config/numen/monitor/worldstate.jsonl`：`refresh` / `read` / `refresh_failed` 均带 topic/dimension/coverage/reason |
| 10 | **重启保留历史** | 杀进程重启后 `read` → `freshness:HISTORICAL`，文案「重启前载入的历史观测，内容无法确认，请刷新」，payload 仍在 |
| 11 | 重启后再刷新回当前 | `refresh` → `read` → `freshness:CURRENT, can_prove_absence:true, age_ms:417` |

关键回执原文（节选）：

```json
{"success":true,"message":"refreshed entities @ minecraft:overworld box=10805,64,2180..10834,83,2209 [category=all] (COMPLETE)","data":{"count":2,"scanned_columns":900,"skipped_columns":0,"coverage":"COMPLETE"}}
{"success":true,"message":"no observation yet; call world_state action=refresh first","data":{"present":false,"freshness":"UNKNOWN"}}
{"success":false,"message":"refresh ... failed: BUDGET_EXCEEDED (request volume 64000 exceeds limit 32768; narrow the range)","data":{"status":"FAILED","reason":"BUDGET_EXCEEDED"}}
{"success":true,"message":"environment 观测于 371664ms 前（重启前载入的历史观测，内容无法确认，请刷新）","data":{"present":true,"freshness":"HISTORICAL"}}
```

结论：**世界观测 V1 的四条红线与读/取分离都在实机上成立**——读不扫描、零/部分/未加载区分、预算明确拒绝、
世界存档进命名空间、重启标历史、失败不静默。

## 二、未能实机验证的（环境阻塞）

**支线执行/推迟/跳过决策（rdd 批次）没能实机验证。** 原因不在代码，在环境：

- 部署需重新编译 `plugins:rdd`，而 Gradle 配置阶段失败：
  `Failed to setup Minecraft, java.io.UncheckedIOException: Failed download after 3 attempts`
  （moddev 与 fabric-loom 都要下载 MC 工件）。
- 根因：**代理/梯子已过期**（用户 2026-10-18 告知），且此前一次失败的重建把
  loom 缓存标记为失效（`ACQUIRED_PREVIOUS_OWNER_DISOWNED, rebuilding loom cache`），
  重建即需联网 → 下载失败。`--offline` 也拦不住 loom/moddev 的直接 HTTP 拉取。
- 因此 mods 里的 `numen-plugin-rdd-*.jar` 仍是 2026-10-08 的旧版，**不含** deferredUntil / decide 改动。

> 世界观测那半能验，是因为它的 jar **今天 12:49 已经编好**（VPN 还在时），本轮只 `deploy.ps1` 复制、
> 无需重新编译，所以绕开了网络。

## 四、环境备注（下次别再踩）

- `mcp-call.js` 的 `key=value` 形式**只吃第 3 个 argv**：多对键值必须整体加引号，
  或直接用 `@文件.json`（推荐，免 shell 引号/代码页之坑）。JSON 内联会被 PS 拆坏。
- 关游戏：`Stop-Process` 杀 java（watchdog 也是 `-Force` 杀，同一惯例）。
- 部署单个已编好的 jar 不需要重新编译：`deploy.ps1 -MutationId <旧mutation> -Instance gpt`。
