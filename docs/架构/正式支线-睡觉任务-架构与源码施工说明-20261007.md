# 正式支线任务：睡觉任务架构与源码施工说明

版本：v0.1，2026-10-07。优先级：**当前最高优先，只做睡觉正规支线**。

本文是给后续施工 AI 的独立上下文。目标不是继续扩展资产积分、死亡支线、机会采集或周期农田，而是把现有“夜间闹钟提示”升级为一个可以临时覆盖主线执行目标的正式硬编码支线任务。

## 1. 用户最终要求

当前最缺的不是另一句提醒，而是支线任务正规军：

1. 夜晚到来前约一分钟，系统判断需要睡觉，创建一次睡觉支线任务。
2. 睡觉支线临时覆盖主线的**执行目标**。主线不被删除、不重规划、不伪造失败。
3. 执行 AI 接收到的当前目标变成“去睡觉”，而不是继续被主线任务牵着走。
4. 监督系统继续运行，但监督目标同步从主线二级目标切换到睡觉支线目标。
5. 硬编码检测真实睡眠状态，不能以 AI 自报或工具返回 success 直接判完成。
6. AI 真实睡着后，或者睡觉支线超过允许时间后跳过，恢复主线执行。
7. 恢复主线时保留原主线指针、状态、acquire 基线和计划代次。
8. 夜间睡觉任务同一游戏夜只触发一次，重启不能重复创建同一个实例。
9. 先预留周期任务接口，未来支持每两三游戏日收割/补种；本轮不实现完整农田周期任务。
10. 死亡支线本轮不改，后续再把它迁入同一正规支线框架。

## 2. 现有源码核查结果

### 2.1 现有独立闹钟：只提示，不接管任务

文件：

```text
E:\restart developing doer\minecraft-numen\api\common\src\main\java\com\dwinovo\numen\api\carrier\CarrierAlarms.java
```

关键事实：

- `CarrierAlarms.ALL` 现在包含 `hungry`、`hungry_soft`、`low_hp`、`night`、`creeper`。
- `evaluate(Facts)` 对闹钟逐条独立求值，返回 `List<Hit>`。
- `night()` 在事实 `night=1` 时命中。
- `night()` 只生成建议文字，例如“天黑了：带着床，可以考虑找个安全的地方睡觉”。
- `wakeWorthy()` 只允许 `creeper` / `low_hp` 的 P0 边沿主动唤醒；夜间闹钟不是急件唤醒。
- 本类是纯 JVM，不导入 Minecraft，不应直接在这里实现“创建任务”或“观察实体是否睡着”。

现有闹钟的正确定位应改为：**事实触发器/候选支线触发器**。不能把 `CarrierAlarms` 继续当作支线状态机，也不能在 `night()` 内部直接改 TaskChain。

### 2.2 现有睡觉工具：一次性床边动作

文件：

```text
E:\restart developing doer\minecraft-numen\core\common\src\main\java\com\dwinovo\numen\core\tools\interact\SleepTool.java
E:\restart developing doer\minecraft-numen\core\common\src\main\java\com\dwinovo\numen\core\tools\SleepOps.java
```

`SleepTool` 的关键契约：

- 工具名是 `sleep`。
- 它要求 AI 已经站在床边。
- 找床由 `scan_blocks`，走路由 `goto`，`sleep` 不负责旅程。
- 调用后返回原版睡眠拒绝原因或成功结果。
- 成功要求 `startSleepInBed` 未拒绝，并且 `self.isSleeping()` 为真。
- 工具成功只表示“此刻服务器确认已经躺下”，不负责等到天亮。

`SleepOps.sleep(...)` 的硬判定代码路径：

```java
Either<Player.BedSleepingProblem, Unit> result = self.startSleepInBed(bedHead);
Player.BedSleepingProblem rejection = result.left().orElse(null);
if (rejection != null) {
    return TaskResult.fail(explain(rejection), data(bedHead, false)).toJson();
}
if (!self.isSleeping()) {
    return TaskResult.fail("the sleep request was accepted but you did not actually enter sleep", ...).toJson();
}
return TaskResult.ok("...server confirms you are sleeping...", data(bedHead, true)).toJson();
```

因此现有 `sleep` 工具可以作为支线的身体动作入口，但它不能单独承担支线生命周期。支线需要持续检测 `isSleeping()`、夜晚状态、超时、目标版本和主线恢复。

### 2.3 现有主线状态所有者

文件：

```text
E:\restart developing doer\minecraft-numen\rdd-core\src\main\java\com\dwinovo\numen\rdd\core\TaskChain.java
E:\restart developing doer\minecraft-numen\rdd-core\src\main\java\com\dwinovo\numen\rdd\core\RddRuntime.java
E:\restart developing doer\minecraft-numen\plugins\rdd\src\main\java\com\dwinovo\numen\plugins\rdd\RddPlugin.java
E:\restart developing doer\minecraft-numen\plugins\rdd\src\main\java\com\dwinovo\numen\plugins\rdd\RddDetector.java
```

已知行为：

- `TaskChain` 是主线进度唯一所有者，保存一级/二级指针、状态、失败/暂停/重规划、计划代次、acquire baseline。
- `RddRuntime` 持有一个 `TaskChain` 和 `AssetRegistry`，并向宿主提供 `startCurrent`、完成、激活和快照接口。
- `RddDetector.onServerTick` 每 20 tick 执行一次检测。
- `RddDetector.tickRuntime` 根据 `PrimaryGoalStatus` 和 `SubtaskStatus` 分流。
- 当前分流只有主线模型：`PENDING/WAITING`、`ACTIVE`、`PAUSED`、`STALLED`、`FAILED`、`AWAITING_SUPERVISOR`、`REPLANNING`、`RECOVERING`。
- `RddPlugin.renderStateContext` 把当前主线二级目标注入执行 AI 的 `<rdd>` 上下文。
- `RddPlugin.nudge` 向内置 AI 注入提醒，但它不是任务所有权切换器。

本次不能直接用 `TaskChain.pauseSubtask` 表达睡觉支线。`PAUSED` 的语义是“这个二级暂时不做”，而睡觉是另一个更高优先级执行目标；把主线二级设成 PAUSED 会污染主线语义、触发暂停复评、影响 owner pause 判定。因此应新增独立支线运行时。

## 3. 最终架构

```text
CarrierAlarms.night()
        │  只产生 night 命中事实
        ▼
SideTaskTrigger / SleepSchedule
        │  按游戏日 + 提前窗口去重
        ▼
SideTaskRuntime<SleepTask>
        │  保存支线生命周期、主线恢复令牌、deadline
        ▼
ActiveTaskSelector  ← 唯一当前目标选择器
        │
        ├─ 当前有效目标：SLEEP_SIDE_TASK
        │       ├─ 执行上下文：去床、等可睡、调用 sleep
        │       ├─ 监督对象：睡觉支线实例
        │       ├─ 硬编码判定：真实 isSleeping / 已醒来 / 超时
        │       └─ 回执归属：sideTaskInstanceId
        │
        └─ 无支线时：MAINLINE
                ├─ 原 TaskChain 指针
                ├─ 原监督和检测
                └─ 原主线回执归属
```

核心原则：

1. `TaskChain` 仍然是主线状态唯一所有者。
2. `SideTaskRuntime` 是支线状态唯一所有者。
3. `ActiveTaskSelector` 是“现在该执行谁”的唯一出口。
4. 任何执行、监督、nudge、上下文和完成回执都必须先经过 Selector。
5. 同一同伴同一时刻只能有一个 `ActiveTask`，禁止主线和睡觉支线双驾驶。
6. 睡觉支线不调用 `TaskChain` 的完成/失败/重规划入口。
7. 主线可以继续被动接收背包和世界观测，但暂停期间不推进当前二级、不累计主线 stall、不消耗主线 retry/replan 预算。

## 4. 建议数据结构

以下是设计契约，类名可以调整，但字段语义不可丢失。

### 4.1 ActiveTask

```java
public sealed interface ActiveTask permits MainlineTaskRef, SideTaskRef {
    UUID companionId();
    String instanceId();
    String taskId();
    TaskScope scope(); // MAINLINE / SIDE
    long generation();
}
```

`generation` 用来拒绝换目标、重启或支线结束后的迟到回执。不能只依赖描述文字或重复的 subtask id。

### 4.2 SleepSideTask

```java
public record SleepSideTask(
        UUID companionId,
        String instanceId,
        String mainlineGoalId,
        String mainlinePrimaryId,
        String mainlineSubtaskId,
        long mainlineGeneration,
        long scheduledGameDay,
        long createdAtGameTime,
        long deadlineGameTime,
        SleepState state,
        String bedDimension,
        BlockPos bedPosition,
        String reason,
        int attemptCount) {}
```

存档必须至少包含：实例 ID、同伴、游戏日、创建/截止 tick、主线恢复令牌、支线状态、床坐标/维度（如果已发现）、最后失败原因和尝试次数。

### 4.3 SideTaskRuntime

```java
public interface SideTaskRuntime {
    Optional<ActiveTask> current(UUID companionId);
    boolean activate(SideTask task);
    void complete(String instanceId, String evidence);
    void skip(String instanceId, String reason);
    void cancel(String instanceId, String reason);
    void restore(...);
}
```

它不拥有主线任务详情，只保存 `MainlineResumeToken`。恢复时必须重新从当前 `RddRuntime` 查主线，而不是把完整 TaskChain 复制到支线。

## 5. 睡觉支线状态机

```text
IDLE
  │ 当前世界为有昼夜循环维度，进入睡前窗口，且本游戏日未处理
  ▼
CREATED
  │ 保存主线恢复令牌，Selector 切换到支线
  ▼
SEEKING_BED
  │ AI 使用 scan_blocks(#minecraft:beds) / goto
  ├─ 找到并到达床边 ───────────────► READY_TO_SLEEP
  ├─ 无床但背包有床：放置流程可由 AI 处理 ► SEEKING_BED
  ├─ 无床且无法准备 ───────────────► WAITING_OR_TIMEOUT
  └─ 危险/主人暂停/主线被清除 ───────► CANCELLED

READY_TO_SLEEP
  │ 只在合适时机调用 sleep；白天拒绝不是工具崩溃
  ├─ server confirms isSleeping() ───► SLEEPING
  ├─ 原版拒绝且仍未超时 ─────────────► READY_TO_SLEEP / SEEKING_BED
  └─ 到 deadline ───────────────────► SKIPPED_TIMEOUT

SLEEPING
  ├─ 正常醒来/睡眠完成事实 ─────────► COMPLETED
  ├─ 主人暂停/世界切换/目标失效 ─────► CANCELLED
  └─ 保护超时 ─────────────────────► SKIPPED_TIMEOUT

COMPLETED / SKIPPED_TIMEOUT / CANCELLED
  │ 记录事件，清除支线 active，恢复主线
  ▼
RESUME_MAINLINE
```

建议优先定义 `SLEEPING` 的结束口径为“真实进入睡眠后已正常完成一轮睡眠并醒来”。如果产品决定“躺下即可完成”，只需替换支线验收器，不改变 Selector 和恢复架构。这个细节必须在实现前冻结。

## 6. 触发规则

触发器读取服务端游戏 tick，不使用机器墙钟。

```java
boolean sleepWindow(
        Level level,
        long gameTime,
        boolean hasDayNightCycle,
        boolean alreadyHandledThisGameDay) {
    if (!hasDayNightCycle || alreadyHandledThisGameDay) return false;
    long dayTime = Math.floorMod(gameTime, 24_000L);
    return dayTime >= SLEEP_TRIGGER_TICK && dayTime < SLEEP_WINDOW_END_TICK;
}
```

“晚上前一分钟”需要施工时根据 Minecraft 时间线明确换算。不要直接把 `night=1` 的首次命中当成唯一触发，因为首次发现夜晚可能已经错过提前窗口。触发去重键建议：

```text
companionId + worldId + gameDay + sleepScheduleVersion
```

以下情况不创建新实例：本游戏日已经 `COMPLETED`、`SKIPPED_TIMEOUT` 或 `CANCELLED`；当前已有有效睡觉支线；世界不支持昼夜循环；当前为死亡回收等不可抢占支线。用户已经明确本次不改死亡支线，因此只读取其占用状态，不迁移其实现。

## 7. 监督与上下文切换

### 7.1 当前目标投影

`RddPlugin.renderStateContext` 现在直接从 `RddRuntime.chain()` 取主线当前二级。施工后不能继续在所有分支里直接取主线，而应：

```java
ActiveTask active = activeTaskSelector.select(companionId);
return active.scope() == SIDE
        ? renderSleepSideContext(active)
        : renderMainlineContext(runtime.chain());
```

睡觉上下文至少说明：

- 当前任务是睡觉支线，优先级高于普通主线执行；
- 当前实例 ID、游戏日、剩余 tick/秒、截止条件；
- 找床用 `scan_blocks` 的 `#minecraft:beds`；
- 走到床边用 `goto`；
- 仅在床边调用 `sleep`；
- `sleep` 返回成功不等于整个支线已完成，必须看支线硬判状态；
- 无床/白天/怪物/距离问题按原版返回原因处理；
- 支线结束后系统会恢复主线。

### 7.2 监督目标

监督器每 tick 只看 Selector 返回的 active task：

- 支线 ACTIVE 时，stall 指纹、nudge、retry 和事件的 `taskId` 必须是支线实例 ID。
- 主线暂停时只记暂停期间的被动观测，不累计“主线无进展”。
- 睡觉支线没有身体动作时，不把“等待夜晚/等待床可睡”误判为卡死；只在支线自己的 deadline 和进度规则下判断。
- 睡觉支线完成、跳过、取消后清理其 stall/nudge/retry 记忆，再恢复主线观察基线。
- 支线 nudge 不能调用主线任务描述，主线 nudge 也不能在支线 active 时发出。

### 7.3 回执路由

任何 `sleep`、`scan_blocks`、`goto` 或监督回执必须附带：

```text
companionId
scope
instanceId
generation
```

消费前校验当前 Selector 仍指向同一个实例。实例不匹配就丢弃并发布 `side_task_stale_result`，不能因为同伴仍存在就把回执应用到新任务。

## 8. 主线暂停和恢复规则

睡觉支线激活时：

- 保存主线 `goalId / primaryId / subtaskId / planRevision / generation`；
- 不调用 `pauseSubtask`；
- 不改主线二级 status；
- 不清 acquire baseline；
- 不调用 `enterReplanningFromStuck`；
- 不把主线标为 FAILED、STALLED 或 AWAITING_SUPERVISOR；
- 停止主线主动执行、主线 nudge、主线 retry 计时；
- 继续缓存真实背包和世界事实。

恢复前重新检查：

1. 主线仍存在；
2. `goalId` 和计划代次仍匹配；
3. 主线当前二级仍是保存令牌对应的节点，或已经被合法外部流程推进；
4. owner 没有清除/替换目标；
5. 世界和同伴仍有效。

不满足时：结束支线但不恢复旧引用，交给当前主线/空闲状态重新选择。满足时：恢复 Selector 到主线，建立新的 stall 观察基线，然后继续原检测流程。

## 9. 周期任务预留，不在本轮实现

睡觉正规支线完成后，通用框架应允许周期模板，但本轮只预留类型，不实现农田逻辑：

```java
record RecurringSideTaskSpec(
        String scheduleId,
        String templateId,
        int intervalGameDays,
        long anchorGameDay,
        MissedPolicy missedPolicy,
        boolean enabled) {}
```

实例字段至少有 `instanceId / scheduleId / scheduledGameDay / state / deadline / progress / generation`。

未来“每两三天收割再补种”应是多步硬编码支线：检查指定田地 → 收割成熟作物 → 补种 → 验证。不能因为背包里有作物就判定完成，必须观察指定区域的成熟/已收割/已补种事实。

本轮禁止把死亡支线改成这个框架。后续迁移时再解决死亡回收窗口、资产损失屏障和正规支线的优先级。

## 10. 推荐源码施工顺序

### P0-SIDE-01：统一当前任务选择器

候选位置：`plugins/rdd`。新增独立运行时/选择器，不直接把支线字段塞入 `TaskChain`。

必须完成：

- 定义 `TaskScope`、`ActiveTask`、`SideTaskRuntime`、`MainlineResumeToken`；
- 所有执行、监督、状态上下文出口从 Selector 取当前目标；
- 同一同伴只允许一个 active 实例；
- 版本/实例 ID 校验；
- 切换事件可观察；
- 主线暂停期间不改主线状态、不消耗主线预算。

### P0-SIDE-02：把夜间闹钟变成睡觉支线触发器

复用 `CarrierAlarms.night` 的事实采样，但在宿主侧新增触发器。`CarrierAlarms` 仍保持纯函数。

必须完成：

- 有昼夜循环维度才触发；
- 使用游戏日与游戏 tick；
- 同游戏日幂等；
- 记录触发原因、版本、快照时间；
- 死亡支线占用时不抢占；
- 目标清除/换目标时撤销旧支线。

### P0-SIDE-03：睡觉支线硬编码检测和生命周期

复用 `SleepOps` 的原版睡眠判定，但不把 `SleepTool` 当作完整支线。

必须完成：

- `sleep` 工具实际成功且 `isSleeping()` 为真才能进入睡眠状态；
- 进入床后持续状态可观察；
- 完成口径明确（建议睡醒）；
- 超时为 `SKIPPED_TIMEOUT`，不是 FAILED；
- 原版拒绝原因进入支线原因；
- 不能因等待夜晚、找床或正常移动直接判 stall。

### P0-SIDE-04：主线恢复与重启

必须完成：

- 支线和恢复 token 原子持久化；
- 重启后旧身体执行 ID 不复用；
- 同游戏日不重复触发；
- 支线完成/超时后只恢复仍有效的主线；
- 主线 acquire baseline 和计划代次保持不变。

### P1-SIDE-05：周期任务接口和农田模板占位

只写接口、状态和可控时钟测试；不接农田自动运行，不改死亡支线。

## 11. 最低测试矩阵

### 11.1 纯 JVM 测试

1. 夜间窗口前触发一次，同一 `gameDay` 第二次不触发。
2. 下界/末地/fixed-time 维度不错误生成睡觉任务。
3. 主线 ACTIVE 时创建支线，主线指针/status/baseline/revision 全部不变。
4. Selector 在支线 active 时只返回支线；支线结束后只返回主线。
5. 旧主线回执在支线 active 时被拒绝或延期，不推进主线。
6. 旧支线回执在实例替换后被拒绝。
7. `sleep` 被原版拒绝、接受但未进入睡眠、真实进入睡眠三种状态分别判断。
8. 超时变成 `SKIPPED_TIMEOUT`，不变成主线 FAILED，不触发主线 replan。
9. 主人暂停优先于睡觉支线；主人清任务后不恢复旧主线。
10. 重启保存支线实例、同夜去重和恢复 token；重启后不重复发送旧身体指令。
11. 支线 active 期间主线 stall/retry/nudge 计数不增长。
12. 周期任务两/三游戏日到期一次，重启和重复 tick 幂等。

### 11.2 Minecraft 实机剧本

1. 白天运行主线，确认没有睡觉支线。
2. 调整到夜前约一分钟，确认只生成一个支线实例。
3. 监测台/上下文显示当前目标从主线变为睡觉，监督事件 `scope=SIDE`。
4. AI 找床、走到床边、调用 `sleep`，检查 `SleepOps` 的真实 `sleeping=true`。
5. 确认夜间支线完成口径后，主线目标恢复，主线继续执行。
6. 无床或怪物阻止睡觉，等到 deadline，确认 `SKIPPED_TIMEOUT` 且主线恢复。
7. 支线期间重启游戏，确认实例恢复且不重复触发/不复用旧 execution id。
8. 主人清目标或换目标后，确认旧支线回执不恢复旧主线。
9. 死亡支线存在时，确认睡觉支线不抢占；死亡逻辑本身不变。
