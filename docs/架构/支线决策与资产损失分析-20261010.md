# 支线决策 + 资产语义与损失分析（2026-10-10）

> 主线保持稳定，支线有选择，资产有用途，损失按实际影响处理。
> 本批只落**前两个可验收阶段**；阶段 3（接入任务调整）按设计**故意不做**——要等分析在实机跑稳。

## 一、本批做了什么

### 阶段 1：支线增加「执行 / 推迟 / 跳过本次」决策

在通用支线引擎 rdd-core 上加了**开之前那一问**（与"开始后超时收尾"的 `SideTaskVerdict.SKIP` 分开）：

| 决策 | 含义 | 行为 |
|---|---|---|
| `EXECUTE` | 执行 | 照旧创建并激活支线 |
| `DEFER` | 推迟 | 不创建；记「推迟到 gameTime 某点」，到点重新决策（等安全停顿点） |
| `SKIP` | 跳过本次 | 不创建；写当日锁 → **本晚不再反复提醒**，下一晚重新判断 |

- 新 SPI：`SideTaskType.decide(companionId, world)`，默认 `EXECUTE`（**旧支线类型零改动**）。
- 新值对象：`SideTaskDecision{Kind, deferTicks, reason}`。
- 世界端口加三个 **default** 事实：`inCombat` / `bodyBusy` / `mainlineObjective`（宿主按需实现）。
- 睡觉支线的规则（确定规则优先）：
  - 主目标文本含「夜晚活动/保持夜晚/通宵…」→ **跳过本次**（主线明确要夜间活动）。
  - 正在战斗（`hurtTime>0`）→ **推迟**（约 10s 后重评估）。
  - 身体被占用（`currentTaskFor != null`，正在引羊/建造）→ **推迟**（约 5s 后重评估）。
  - 否则 → 执行。
- 推迟冷却**至少一拍**（宿主约 20 tick 调一次），避免每拍重复决策；推迟状态**随引擎一起持久化**，重启不丢。
- 关键边界：**跳过 ≠ 完成 ≠ 永久关闭**；**推迟不覆盖正在执行的身体任务**（支线只冻结主线检测，
  身体任务是否暂停/恢复仍走既有运行时——本批没碰 body slot，安全）。

### 阶段 2：资产语义 + 损失影响分析（纯逻辑）

- `AssetSemantics`：把「重要程度」（重要/次要/与当前目标无关）和「使用性质」
  （消耗品/装备工具/材料/任务物品）**拆成两个字段**，外加 `服务目标 / 所需能力或数量 / 来源 / 可替代条件`。
  重要程度**随目标变化**（目标取消 → 标 `IRRELEVANT`，损失不再触发动作）。
- `LossImpactAnalyzer`：替代"重要丢一个就判、次要丢多个才判"的评分式决策。
  **重要等级决定值不值得关注，剩余能力决定需不需要行动**。输出
  「影响了哪些目标 / 备用是否足够 / 建议处理」——**只产事实与建议，不动任务链**。

  建议类型：

  | 建议 | 何时 |
  |---|---|
  | `NONE` | 无关资产 / 已被捡回 / 正常消耗 |
  | `SWAP_BACKUP` | 重要资产丢了，但需求仍被备用/替代满足 → 换装继续 |
  | `CONFIRM_STOCK` | 次要受影响，**或尚未确认丢失**（回收未结束/区块未加载） |
  | `SUPPLEMENT` | 重要能力缺口，需求已不满足 |

  两条边界：① 传进去的是**净损失**（已确认仍缺失），不是死亡瞬间快照——捡回了就不该报永久损失；
  ② `lossConfirmed=false` 时不下"永久丢失"结论，只建议先确认库存。

## 四、故意没做（阶段 3 的门）

- **不自动改任务链**：损失分析只输出建议，不插入补充支线、不调整主线。设计明确"分析可靠后再接入"。
- **不追问模型**：决策全是确定规则；"需要取舍时问 AI"留待后续（不要每 tick 问一次模型）。
- 位置的"能力"判据仍是**数量/替代**的近似（如石镐不能替代钻石镐靠需求键区分），
  真正的"能不能挖黑曜石"能力模型未做。

## 五、实机验收清单（接手先跑）

1. 夜里正常状态下，睡觉支线**照常**触发执行。
2. 夜间引诱怪物（主线带"保持夜晚"意图）时，睡觉支线**跳过本次**，且本晚不再反复提醒。
3. 引羊过门途中（身体忙），睡觉支线**推迟**，门过完/身体空出后**自动执行**。
4. 重启游戏后，推迟状态**不丢**（不会因为重启而立刻重复触发）。
5. `logs/monitor/rdd.jsonl`（或对应通道）能看到 `side_task_deferred` / `side_task_skipped_occurrence` 及原因。
