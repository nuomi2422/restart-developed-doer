## 开发顺序

先读 README、engineering-standards 和相关现有 `self-compile-*.md`；确认任务档位；列影响面和消费者；在关键路径加入 debug；先写失败测试，再写最小实现；完成后按 SOP 编译、部署、验证、commit、push。

## 状态与权限

所有状态只能按 README 的状态机转移；每个候选创建 `candidate_id`，记录 `parent_commit`、变更文件/行和测试实例。Executor、Supervisor、Self-Compile、Test Gate、Promotion Gate、Watchdog、人工审批各自只有规定的转移权限。

## 测试要求

测试至少覆盖正常、空值、特殊字符、并发、重复唤醒、端口冲突、孤儿锁、Monitor 失联、游戏崩溃、连续恢复失败和证据缺失。MCP 返回成功必须与 Monitor 事件和世界事实对撞；编译成功不能直接晋级。

## Review 与模型调用

工具级可自行完成；模块级由 Codex 主指挥官规划并验收，Claude CLI/OpenCode 在边界内协作；架构级走完整九步流。网页模型开启思考/推理模式后只输出意见、风险和替代方案，不进入控制面，不执行、部署或回滚。

## 提交格式

```text

```

提交说明必须附测试命令、结果、事件证据路径和未完成项；没有证据就不能宣称完成。
