# RDD 自编译系统维护者手册

## 维护目标

维护者负责保持 Claude/Codex Bridge、心跳、Monitor、实例注册表、自编译闭环和证据链可恢复；不以“脚本能运行”代替闭合验证。

## 日常巡检

1. 检查 `E:\新建文件夹\rdd架构\自编译系统\README.md` 与本手册的状态是否真实。
2. 检查 `events/*.jsonl` 是否持续产生结构化事件，且包含 `task_id/execution_id/candidate_id`。
3. 检查 InstanceRegistry、`instance.lock`、`monitor.lock` 是否有孤儿锁；确认 8765/8766 端口归属。
4. 检查心跳最近一次唤醒、恢复或自停记录；无任务时不应启动 AI。
5. 检查 Watchdog 是否只做基础设施恢复；出现重规划行为立即触发 Kill Switch。

## 故障处理顺序

先保全现场（日志、事件、进程命令行、candidate_id），再分类为 BUILD/CONTRACT/TOOL/RUNTIME/TEST/ARCHITECTURE/UNKNOWN；禁止直接删日志或无限重启。连续两次找不到根因时止损并交接。

## 版本与回滚

每个变更使用 `[模块名][CANDIDATE-ID]` commit 前缀；候选只在 `test` 实验。Promotion Gate 全绿后才可进入 `gpt`，生产仍需人工批准。回滚优先回退单个模块或 active 指针，不整体抹除宿主。

## 交接要求

交接必须写明当前状态、最后事件、候选 ID、父 commit、证据路径、已尝试动作、止损原因和下一步；另一个 AI 只读本手册、README 和交接记录即可恢复工作。
