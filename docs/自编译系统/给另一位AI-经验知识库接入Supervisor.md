## 实施方向

1. 分清两种知识：可移植的 MC 基础攻略；该同伴真实成功 / 失败积累的经验。不要把全部 Markdown 每轮塞进请求。
2. 按目标、当前阶段和已知失败事实召回少量相关内容，设置条目数与文本预算。保留来源 / 条目 ID、成熟度及推荐处理；知识作为参考资料，不获得修改任务或执行工具的权限。
3. 在最终发送给 Supervisor 的请求中包含选中的知识正文；主线程已有请求采集会记录它。只把结果写进日志、未放进请求，仍算未接通。
4. 空库、插件未安装、文件损坏、无命中时明确标记缺失或降级，不能伪造知识。依赖复用现有插件边界，不把 experience-core 再打包一份进 RDD，不引入新的向量服务。
5. 按当前仓库规则实现、测试并给 Codex 审查；普通技术取舍自主处理，不为每一步向用户提问。
