# 软件工程规范

本目录是 RDD 自编译系统的软件工程门禁，和九步编程流配套使用。

## 三档任务

1. 工具级：单工具、简单测试工具、局部脚本或文档修正。AI 自主完成，Codex review 可选，不等待用户。
2. 模块级：Bridge、Harness、心跳、Monitor、双实例、自编译子模块。Codex 负责规划和验收，Claude/OpenCode 在批准的模块边界内执行并回报；跨边界或高危冲突才升级。
3. 架构级：改变 RDD 核心、跨模块契约、生产或安全边界。完整九步流，多模型评审，核心取舍请求用户批准。

隐藏复杂度只能升档，不能降档；“还有东西没写完”不是暂停理由。

## 九步流与执行门

架构级任务必须经过分类、探索、逐问澄清、方案比较、外脑意见、设计、用户批准、实现计划和闭合验证。工具级/模块级可自主推进，但仍必须留下设计摘要、影响面、测试和事实证据。

所有任务都遵守：

- 接口变更先查消费者并做契约回归；
- 首测通过后立即做边界、异常、极端和多数据测试；
- 关键路径同步埋 debug，日志回答入口、输入、分支、输出；
- 编译成功或 MCP 返回 OK 不等于真实行为成功；
- commit 使用 `[模块名]` 前缀并保留单模块回滚点；
- 连续两次失败仍找不到根因时止损，不无限硬磕。

## 模型协作

Codex 是主指挥官和最终技术审查者，Claude CLI 与 OpenCode 是受控下位 Harness。网页模型只在架构/自变异设计、连续两次失败、生产交付前或用户要求时调用，并开启思考/推理模式；只记录意见摘要，不索要隐藏思维链。最终批准必须基于源码、测试、日志和真实 MC 世界证据。

## 长线任务

通宵测试、通关 MC、监测和自变异循环必须使用心跳与看门狗规范；AI 每次任务注入都收到继续条件和止损条件提醒。

## 维护硬契约

- Markdown 是解释层，结构化 `events/*.jsonl` 才是机器控制事实层。
- 每个候选必须有 `candidate_id` 和 `parent_commit`；没有审计链不得晋级。
- Promotion Gate 未全部通过不得进入 `gpt`；生产晋级必须人工批准。
- Watchdog 只恢复进程、端口和监测基础设施，不参与任务重规划。
- 实例使用 InstanceRegistry、实例锁和监测锁；端口由注册表分配，禁止硬编码共享端口。
- Kill Switch 触发后只允许保全现场、写事件和等待人工接管。
