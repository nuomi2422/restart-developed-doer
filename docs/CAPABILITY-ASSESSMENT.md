# 能力评估（Honest Capability Assessment）

> **性质：写代码者（自编译系统）的诚实自评**——不掺水、不拔高。
> 与 [`REAL-VERIFICATION-RESULTS.md`](REAL-VERIFICATION-RESULTS.md)（已验证什么）互补：
> 那份说"真跑通了什么"，这份说"极限到哪、天花板在哪、别人怎么看、下一步该干嘛"。
> 日期：2026-08-31

---

## 一句话定级

> **一个"单次能自主完成小时级大型任务、有监督兜底、能自造工具"的 MC Agent Runtime——
> 骨架扎实，真机验证诚实，但离"可复现的强鲁棒系统"还差一段系统实验。**

---

## 一、已证实的极限（真跑过，不是预测）

```text
从零 → 木/石工具 → 铁器 → 熔炼GUI → 钻石镐 → 挖黑曜石
├─ 挖钻石全链（rdd 背包实测 diamond:9）
├─ 铁甲全链
└─ 时长尺度：小时级，含卡死自动拍醒、失败自动重试
```

这是 vanilla MC 里一个**真正的多阶段工具链**——不是"采个木头"这种玩具任务。
多数 MC agent 项目死在这里，本项目真机跑通（详见 [REAL-VERIFICATION-RESULTS.md](REAL-VERIFICATION-RESULTS.md)）。

---

## 二、理想极限（架构上可达，但**未全程验证**）

```text
终极目标：从零 → 末影龙 → 通关（End Game）
│  前中期资源 → 铁 → 钻石 → 下界 → 末地 → 打龙
│     ↑已验证     ↑已验证  ↑部分  ↑未      ↑未
```

- **每一段单独看都接近可行**；
- **但"串联起来"的全程稳定性从没验证过**——每段各有失败模式，串联后失败率累积。
  这是"理想 vs 现实"的真实差距：挖钻石通了 ≠ 通关能通。

---

## 三、结构性天花板（5 条硬伤，别人一戳就中）

```text
1. 上下文/注意力有限 → 长任务"忘记目标"/陷入局部最优（挖矿卡死）
   RDD 能拍醒，但不能根治 —— 治标不治本
2. assist 自主性边界 → AI 收到"缺工具调自编译"引导却不调（真机验证卡在这）
   = 自变异闭环没真正闭环，这是最大硬伤
3. 感知盲区 → 背包靠轮询、世界靠扫描，理解是"稀疏的"
4. expmem 语义检索未做 → 经验只能词法召回，"同义不同字"学不进去
5. GUI 交互脆弱 → 熔炼/合成靠坐标点击，最容易卡
```

## 四、别人会怎么评判（三拨人）

### 开源社区（最友善）
> "Demo 冲击力强，真挖到钻石。卡死监督是工程亮点，自编译是差异化。文档诚实（真机 vs 声明分开），比一堆 PPT 强。"
> 但："构建门槛太高，要自己建 Numen 宿主，跑不起来就只剩看。"

### 研究者 / 审稿人（最严苛）
```text
加分：
  · 真机验证（非声明）
  · 监督架构（STALLED→拍醒→恢复）
  · 自编译宿主化（缺工具自造）
  · 模块化 commit 可回滚（工程纪律）

扣分：
  · 与 Voyager（NVIDIA 2023）比没有本质新东西——核心玩法"LLM 驱动 MC Agent"不新
  · 没有重复实验——1 次跑通 ≠ 成功率，他们要 10 次独立运行的成功率
  · 依赖宿主——"脱离 Numen 还能跑吗？"
  · assist 边界暴露自主性没闭环
  · 规模小（125 文件），无与 SOTA 的定量对比

判定：能发 demo / workshop 论文；离顶会 main track 差系统实验 + 对比 + 规模。
```

### 路人用户（最大众）
> "哇 AI 自己挖钻石还不会被卡死"——然后发现要自己建模组，关掉。

## 五、提升路线（把"能跑"变"能打"）

```text
P0  同一任务重复跑 10 次，报成功率
    → 把"能跑一次"变成"可复现的成功率"，这是别人最想看的数字
P1  打通 assist → 自编译强制调用
    → 补上自主性闭环这个最大硬伤（RDD 直接发起自编译请求）
P2  expmem 接向量检索（BGE embedding + 灵魂核心向量索引）
    → 把"学经验"从词法变真语义
P3  通关链全程串联验证一次（哪怕跌跌撞撞）
    → 用一次完整 End Game 跑证明"理想极限"真实存在
```

骨架（五模块 + 监督 + 自编译 + 诚实文档）是真资产；下一步不是加功能，是**证明可复现**。
