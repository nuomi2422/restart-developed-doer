### 1️⃣ 修 `ps=COMPLETED` + `st=PENDING` 的恢复态矛盾 【模块级】

**现象**（19:33 实机）：重启后链处于 `primaryStatus=COMPLETED` 而当前二级 `PENDING`，
`rdd_submit` 与 `startCurrent` 双双被拒：`current subtask cannot start`。
结果是整条链死在新任务无法启动，PAUSE 也就无从复验。

**卡在哪**：`TaskChain` 的恢复/提交路径没处理"一级已完成但当前二级尚未启动"这个组合。
`startCurrent()` 的守卫是 `primaryStatus != ACTIVE || status != PENDING → 拒绝`，
恢复逻辑却会留下 `COMPLETED + PENDING` 这个自相矛盾的组合。

**先查消费者**：`startCurrent` 的 3 处调用（`RddDetector` / `RddGoalDriver` / 提交工具）+
`resumeFromReplanning` / `applySupervisorDecision` 的出口。
**别用**「把守卫放宽成 `primaryStatus != COMPLETED`」这种糊法——那是把矛盾藏起来。
