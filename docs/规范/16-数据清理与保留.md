# 16 · 数据清理与保留（防「越积越杂」）

> 用户 2026-09-28 要求：**系统缺一个清理流程** —— 记录不清理就"很多很杂"。本文件定义**保留策略 + 清理流程 + 脚本**。
> 配套脚本：`rdd-selfcompile\scripts\cleanup-logs.ps1`（默认只报告，`-Apply` 才删）。

## 一、为什么要有（真实证据）

2026-09-28 实测：`<实例>\config\numen\` 已涨到 **1,911 MB**，其中——

| 数据 | 体量 | 根因 |
|---|---|---|
| `monitor\context-*.jsonl` | **93 个 / 1,502 MB（占 93%）** | **只轮转、从不清理** |
| `monitor-archive\rdd-…-288MB.jsonl` | 274.9 MB | 手工留的大档案，无压缩/过期策略 |
| `monitor\rdd-*.jsonl` | 5 个 / 80 MB | 有轮转 + 清超量归档（RddMonitor 已带） |
| 活文件 `context/rdd/tools/ai/state/events.jsonl` | ~30 MB | 正常，插件自动轮转 |

**根因对照（关键）**：
- `RddMonitor.java` / `RddInstrumentation.java`：`MAX_FILE_BYTES=16MB` **轮转**，且 rotate 时「**再清出目录里的超量归档**」→ 这两个**会自清**。
- `context-*.jsonl`（Numen 上下文层）：**只轮转、没有清理逻辑** → 就是它在无限涨。
- 消费者核查：监测台 `server.mjs:19-20` 只读**活文件** `context.jsonl` / `rdd.jsonl`，**不读任何轮转文件**；网页只展示有界近期记录（非全历史检索）。
  → **轮转文件零消费者**，清理它们不影响监测台。

## 二、保留策略（谁留、留多久）

| 数据 | 位置 | 策略 | 默认值 |
|---|---|---|---|
| `context-*.jsonl` 轮转 | `<实例>\config\numen\monitor\` | 只留最新 N 个，其余删 | **10** |
| `rdd-/tools-/ai-/state-/events-*.jsonl` 轮转 | 同上 | 只留最新 N 个 | **5** |
| 活文件 `*.jsonl`（无时间戳） | 同上 | **永不删**（插件自动轮转） | — |
| `monitor-archive\*.jsonl` | `<实例>\config\numen\monitor-archive\` | 留最新 N；**>50MB 且 >1 天的 → gzip**（保证据、省 85%+） | N=**3** |
| 游戏内 `selfcompile\mutations\` | `<实例>\config\numen\selfcompile\mutations\` | 只留最新 N 个工作区 | **10** |
| 外部 `mutations\` | `rdd-selfcompile\mutations\` | **不删**（小，是闭环证据） | — |
| `report\` 产物 | `rdd-selfcompile\report\` | 留最新 N | **3** |
| `scripts\requests\req-*.json` | `rdd-selfcompile\scripts\requests\` | 留最新 5 | **5** |
| `drive-heartbeat.log` | `rdd-selfcompile\scripts\` | >1MB → 轮转为 `.1.log`（不删历史，保 1 份） | **1MB** |
| `AGENTS.backup\` | `~\.config\opencode\` | 留最新 10 | **10** |
| `测试日志.md` / `09-更新日志.md` | `rdd架构\` / 统一版 | 暂不自动清；超 512KB/256KB 时**归档**为 `*-YYYYMM.md` | 手动 |
| `selfcompile\stable\`（版本库） | `rdd-selfcompile\selfcompile\` | **绝不清理**（回滚依赖） | — |

## 三、清理流程（何时清、怎么清）

**触发时机**：
1. **每轮闭环收尾**（`15` 收尾检测第 3 项）。
2. **进游戏前后**（monitor 会涨）。
3. 感觉"杂了 / 盘满了"时。
4. 建议：挂进 `every-10min-drive.ps1` 或收尾脚本，定期自动跑。

**命令**：
```powershell
# 1) 先看会删什么（默认就是只报告，安全）
powershell -NoProfile -ExecutionPolicy Bypass -File D:\rdd\workspace\rdd-selfcompile\scripts\cleanup-logs.ps1

# 2) 确认后执行
powershell -NoProfile -ExecutionPolicy Bypass -File ...\cleanup-logs.ps1 -Apply

# 3) 换实例 / 改保留数
powershell ... -File ...\cleanup-logs.ps1 -Apply -InstanceDir "D:\rdd\mc\.minecraft\versions\<实例>" -ContextKeep 15
```

**安全保证（脚本设计）**：
- 默认**只报告**，必须显式 `-Apply`。
- 只匹配**轮转命名**（`context-<时间戳>.jsonl`），**绝不删活文件** `context.jsonl`。
- 不碰 `selfcompile\stable`、不碰源码、不碰 `.git`。

**首次执行记录（2026-09-28）**：`1,911.3 MB → 309.3 MB`，**净释放 1,602 MB**（83 个旧 context 轮转 + 归档 gzip：275MB→13.4MB）。

## 四、为什么不直接改代码自清（决策）

- `context-*.jsonl` 无清理逻辑**是缺陷**，但修它属 Numen 源码改动（**架构级/模块级**），需编译部署+真机验证。
- 本流程先用**运维脚本**兜住（零代码、零风险、立即生效），**代码侧补丁列为待办**（见 §五）。
