## 二 · 失败模式（症状 → 根因 → 论文给的对策）

### F1 · 长时序错误复合（不是某一步错，是每步 5% 错累积成 100% 错）
- **症状**：单个动作都像对的，跑 500 步后任务彻底走偏，且无法归因到哪一步。
- **根因**：LogicGuard 原文 —— "in long horizon sequential planning tasks, their errors compound"。
  LARM 补了另一半根因：**长时序探索里经典 RL 奖励会消失**（reward vanishment），没有奖励就没有纠偏信号。
- **对策**：
  - **LogicGuard**（arXiv:2507.03293）：actor-critic 架构，critic 读**完整轨迹**并产出**时序逻辑（LTL）约束**去约束 actor。
    模型无关 —— 任何 LLM planner 当 actor 都行，LogicGuard 是套生成逻辑规则的外壳。
  - **不要靠 prompt 加提醒，要靠架构层加约束**（这是本文最重要的一条方法论）。

### F2 · 真正卡死的不是规划层，是低层控制器的重复失败
- **症状**：plan 看着很合理，但低层老是同一个动作失败 → 重试 → 再失败。
- **根因**：MrSteve（ICLR 2025）明确写 "low-level controllers frequently become performance bottlenecks
  due to **repeated execution failures**"，并把主因归给 **episodic memory 缺失**。
  WISE 进一步：**不只是缺记忆，是 what-where-when 记忆与 which-why 推理脱节**。
  WISE 还点名 MrSteve 的做法有洞：用**特征相似度检索**，换视角就召不回。
- **对策**：
  - **MrSteve / Place Event Memory**：按「什么 / 哪里 / 何时」组织空间+事件数据 → 长时序导航召回。
  - **WISE / Causal Event Graph**：在情节记忆里显式加**因果结构**，把观测连到任务相关性；
    换视角鲁棒 + 支持**机会主义任务重排**（路上看到相关东西就插队）。
  - **PEAM**（arXiv:2605.27762）：**把失败当一等训练信号** —— 失败-纠正轨迹对一起内化，
    让 agent 不只学「什么成功」，还学「纠正动作和失败动作差在哪」。

### F3 · 先验知识错了，prompt 改不动（有反馈也改不动）
- **症状**：LLM 坚信某个错误配方/前置关系，你反复纠正、连给失败反馈，它下次还这么干。
- **根因**：XENON 原文 —— "LLMs often begin with **flawed priors and fail to correct them through prompting,
  even with feedback**"。这是本项目「双驾驶」问题的镜像版。
- **对策**：**XENON**（ICLR 2026）—— 用经验**算法化地改写**知识：
  - **Adaptive Dependency Graph**：用过去的成功修正物品依赖关系（原木→木板这种）
  - **Failure-aware Action Memory**：用过去的失败修正动作知识
  - 效果：**7B XENON 反超靠更大专有模型的 agent** → 说明"补知识"比"换大模型"划算。

### F4 · Context Collapse：动作做了跟没做一样，世界不给你反馈
- **症状**：agent 反复执行同一串动作，预测的"未来"几乎不变 → 它无法判断自己有没有用 → 学不到东西。
- **根因**：ActSWM（arXiv:2607.26712）命名的 **Context Collapse**：
  自回归潜在预测器对**不同动作序列产出几乎无法区分的未来**（预测精度很高但动作不敏感）。
- **对策**：transition-separation 原则 —— 「有用的潜在动力学模型必须让不同动作的未来保持可区分」；
  把动作敏感性做成 rollout 的**约束**而不是辅助预测目标。

### F5 · 写出来的程序没法验证、没法拼新约束、没法从失败轨迹里修
- **症状**：让 LLM 写代码控制 agent，它能写出「看起来对」的行为，但：
  你没法验证它有没有守住约束，没法把新约束跟老技能组合，失败了也没个稳定对象去修。
- **根因**：CEDAR（arXiv:2608.27797）原文 —— "their free-form programs provide **no stable object to
  verify, compose with new constraints, or repair from a failing trace**"。
  同一篇还指出：像「晚上要睡觉」「待在某个生物群系」这种**约束在世界变化时不会被保持住**。
- **对策**：把技能和规格都表示成**确定性有限状态自动机**，约束变成可执行对象；
  「学到的技能 ∩ 学到的约束」直接求交得到一个**构造上就满足约束**的控制器 —— 不用反复 prompt。

### F6 · AI 不会说「这题做不了」，于是硬打末影龙
- **症状**：装备不足、路径不通、前置缺了，AI 仍然一头撞上去，死了重来。
- **根因**：Plancraft（arXiv:2412.21033）专门塞了**故意不可解**的样本，测「agent 能不能判断可不可解」，
  结论是 LLM/VLM 在这类规划题上表现挣扎。
  MineEvolve 独立复述同一现象：长前置链任务「frequently disrupted by
  **missing tools, blocked paths, GUI failures, or stagnant execution**」。
- **对策**：Plan 层加**前置条件检查**（缺料就先补料，别硬上）+ 显式的**可行性判定出口**。

### F7 · 自我验证不可靠 → 自证成功
- **症状**：agent 自己说做完了，世界没变。
- **根因**：Voyager 论文自列局限 —— **自验证不可靠**。MineNPC-Task 玩家组也指出记忆持久性不足。
- **对策**：StructAgent 的**验证器支撑状态转移 + 证据驱动完成**；
  任务范式里预置**故意不可解样本**做持续体检。

### F8 · token 与推理深度烧钱
- **对策（三条，都有用）**：
  - **WALL-E**：不用冗长轨迹喂 LLM，改喂**少量抽取出来的规则** → token 降到 60–80%，成功率还 +15–30%。
  - **Game-TARS / Sparse-Thinking**：**按需调推理深度**，平衡 reasoning depth 与 inference cost。
  - **Game-TARS / decaying continual loss**：专门治 **causal confusion（因果混淆）**。

### F9 · 多智能体：说太多反而更差
- **症状**：让 agent 之间互相沟通详细计划，越沟通越糟。
- **根因**：MINDcraft —— 性能**掉 15%**。瓶颈是自然语言通信效率，不是推理能力。

### F10 · 经验堆了一堆但迁移不出去
- **对策**：Echo（arXiv:2604.05533）—— 把可复用知识拆成**五维**：
  structure / attribute / process / function / interaction，
  靠 **In-Context Analogy Learning** 检索适配。效果 1.3–1.7×，并出现**连锁解锁**。

### F11 · 空间一致性崩了 → 原地横跳永不完成
- **症状**：站在树冠 y=62，对着 y=47 的地面目标判「已到达」，然后左右横跳到天荒地老。
- **根因**：LoopNav（arXiv:2505.22976）提出 **Scene Graph Consistency Score** 专门量化这个问题；
  WorldPack 用 FoV 重叠度做差异化压缩。**这是空间一致性问题，不是寻路问题。**

## 三 · 成功打法的共同骨架（把上面 14 篇叠起来看）

```
  ① 约束/规格要能验证、能组合、能从失败轨迹修
     → 表示成确定性对象（有限状态机 / 依赖图 / LTL 约束），别停在 prompt 里
  ② 执行反馈必须 typed，不能是一坨自然语言
     → MineEvolve 的 Monitor：state change / inventory change / failure type /
       progress signal / stagnation indicator
  ③ typed 反馈 → 分流成「技能（来自成功）」和「补救（来自失败/停滞）」
     → Inducer 分流
  ④ 知识要过一道 validate / merge / filter / retrieve
     → Curator；配写入闸（防静默覆盖）
  ⑤ 反复失败或停滞时，用知识去修「计划未完成的那一段」，不是从头重规划
     → Adaptor（关键：局部修补，不是整体重规划）
  ⑥ 知识要算法化改写，不是靠 prompt 纠正
     → XENON：依赖图用成功修正，动作知识用失败修正
  ⑦ 记忆要带因果结构，不是相似度检索
     → Causal Event Graph；what-where-when + which-why 都要
  ⑧ 反馈即训练信号，失败-纠正成对
     → PEAM
  ⑨ token 用规则压缩 + 推理深度按需
     → WALL-E / Game-TARS
  ⑩ 人类介入要「按需请求推理」，不是「喊救命」
     → AHCE：+32% / +70%
```
