# 14 · 运维手册（怎么看 / 怎么修）

> 用户强调：**运维非常重要**。功能能跑但没人看得懂 = 负债。

## 一、日常启动 / 停止

> ⚠️ **MC 运行时长（用户 2026-10-02 更新）**：**默认 2 小时（120 分钟）**，不再有「10 分钟/次」的检测或自动关。
> 旧的 2026-09-27 铁律（在线 ≤10 分钟）**已作废** —— 不要再按它写脚本或拦启动。
> 自动关只为防空转耗电，不是门禁；要提前关用 `mc-instance.ps1 -Action Stop` / `mc-start.js --stop`。

### 内存大户清单（本机物理仅 7.7GB · 远控易断根因）

| 大户 | 典型占用 | 说明 |
|---|---|---|
| **msedgewebview2** | **~1.7GB** | ChatGPT 桌面 / Edge WebView 常驻（最大户） |
| Minecraft(modpack) java | ~1.8–3.6GB | 开了就顶内存 |
| OpenCode | ~1GB（多进程） | **本体，不能关** |
| msedge / 浏览器 | ~0.2–0.5GB | 用户可能在用 |
| MsMpEng(Defender) | ~0.15GB | 系统 |

> 实测：MC 关着时全机空闲也常只剩 **0.5–0.8GB**；再开 MC → 提交/换页压力猛增 → 远控断。

### 在线看门狗（用户离线自动关游戏）

规则（用户 2026-10-02 更新）：**默认 120 分钟**；旧的「10 分钟没收到用户消息 = 用户离线 → 自动关 MC」已作废。
- 机制：agent **每收到用户消息就刷新** `scripts\presence-last-user.txt`；`presence-watchdog.ps1`（`-Loop`, `-StaleMinutes 120`）每 60s 检查，超时且 MC 在跑 → 关 MC。
- 启动：`presence-watchdog.bat`（后台常驻）；日志 `presence-watchdog.log`。
- 与 `mc-watchdog.ps1`（到点关）互补：一个是"到时间"，一个是"用户走了"。

### 远控救急开关

`E:\restart developing doer\rdd-selfcompile\scripts\rescue-remote.ps1`

```powershell
# 只报告（默认）：
powershell -File rescue-remote.ps1
# 真释放（关 MC + msedgewebview2）：
powershell -File rescue-remote.ps1 -Apply
# 连浏览器也关（更狠）：
powershell -File rescue-remote.ps1 -Apply -CloseBrowsers
```
- 目标：Minecraft(modpack java) + `msedgewebview2`（+ 浏览器，需 `-CloseBrowsers`）。
- **绝不碰 OpenCode 本体**（否则把 AI 关了）。
- 原则：**MC 与 ChatGPT 桌面/WebView 尽量二选一**；用户要在场远控时先跑救急开关。

|---|---|---|

## 二、健康检查（一眼）

- **watchdog**：`Get-Content rdd-selfcompile\scripts\drive-heartbeat.log -Tail 1` 时间应新鲜（<10min）。
- **监测台**：`http://127.0.0.1:8776/api/health`；或打开页面看连接点。
- **MCP**：`node scripts\numen-mcp.js list`（应列工具）；`get_self_status` 有同伴。
- **RDD**：`node scripts\numen-mcp.js call rdd_status <同伴>` 看 `primary_status/subtask_status`。

## 三、常见故障 → 处置

| 现象 | 先查 | 处置 |
|---|---|---|
| 不产出 / 周期 `loop_detected` / `ai.jsonl` tools 不变 | **网络/provider**（最常见） | 恢复网络；别急着改代码 |
| `primary_waiting: dependency assets not present` 长期 | 该级 `waitFor` | 核是否被误加硬门（RL-3） |
| 监测台没数据 | `NUMEN_MONITOR_DIR` | 用正确实例目录重启 server |
| W 浏览器黑屏/点不动 | 是否后台进程启动 | 让**用户双击** `W-browser.bat` |
| `.ps1` 报语法错 / 中文乱码 | 是否含中文注释 | 纯 ASCII 最保险；**含中文则必须存 UTF-8 BOM**（PS 5.1 会把无 BOM 的 UTF-8 当 ANSI 读） |
| 磁盘被 `numen\` 吃满 | `monitor\context-*.jsonl` 是否堆积 | 跑 `cleanup-logs.ps1`（见 §七 / `16`） |
| MCP 连不上 8765 | MC 是否在跑、config 是否 enabled | 起 MC / 改 config |
| 改完 opencode.json 不生效 | — | **重启 opencode** |

## 七、数据清理（防「越积越杂」）

> 完整策略见 `16-数据清理与保留.md`。**核心**：轮转日志会无限涨（2026-09-28 实测 `monitor` 已达 1.6GB）。

```powershell
# 只报告（默认，安全）
powershell -NoProfile -ExecutionPolicy Bypass -File E:\restart developing doer\rdd-selfcompile\scripts\cleanup-logs.ps1
# 确认后执行
powershell ... -File ...\cleanup-logs.ps1 -Apply
```

- 保 `context-*.jsonl` 最新 10、`rdd-*.jsonl` 最新 5、`monitor-archive` 大档案 gzip、游戏内 mutation 最新 10 等。
- **绝不删**活文件（`context.jsonl` 等）、`selfcompile\stable`（回滚库）、源码。
- **何时跑**：每轮收尾（`15` 第 3 项）、进游戏前后、盘满时。
- 首次实跑：`1,911 MB → 309 MB`（释放 1.6GB）。
