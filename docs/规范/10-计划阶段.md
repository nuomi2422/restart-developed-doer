# 10 · 计划阶段（①计划统筹 这一阶段干什么）

> 本阶段目标：把「用户口述的一句话」变成一份**所有 AI 都不会跑偏的最终架构文档**。
> 计划没定稿不许写码。产出物 = 目标书 + 计划书 + 审稿 + **最终架构文档**。

## 一、默认路线（绝大多数任务走这条）

```
   用户目标
     │
     ├─▶ ① 当前模型自己写计划（opencode 就能写）
     │      ★ 写文件用 write 工具，不要 node -e 内联（会被 PS 引号规则拆坏）
     │
     ├─▶ ② W 池互审（见本文件「三、互审工具」表）→ GLM 为主，可加 DeepSeek
     │      固定画像 · 浏览器不许关 · 记住上次用哪个
     │
     ├─▶ ③ 汇总各家意见 → 逐条标注【采纳】/【驳回 理由】
     │
     ├─▶ ④ 冻结成「最终架构文档」
     │      stager put --kind arch --title "最终架构文档-vN"
     │      ★ 这份是所有 AI 的锚，每阶段都要回头读，防跑偏
     │
     └─▶ ⑤ 计划成立 → stager next 进编码
```

### 探针：互审前先探（必做，2026-09-30 用户定）

**问真问题之前，先跑探针。** 探针给每家发一个带随机数的问题，核对答案里有没有那个数：

```powershell

| 结果 | 怎么办 |
|---|---|

| 有 ✘（退出码 1） | ⛔ **先别问** —— 那家抓到的是旧答案/答非所问，用了会污染审稿结论 |

```

**为什么要探**：2026-09-30 实测踩坑 —— GLM **浏览器里答对了**，但落盘文件里存的是**上一轮**的答案。
光看「登录态在 / ok:true」发现不了，**必须拿一个只有这次才可能答对的随机数去核对**。

**记录**：`E:\restart developing doer\rdd-selfcompile\report\w-probe-<时间>.json`

### ★ 外脑怎么用：找分歧，不是数票

**共识是外脑最低效的用法。** 4 家都说「建议 fail-fast」→ 你得到一个你已经知道的结论。

| 4 家的关系 | 怎么处理 |
|---|---|
| **全部一致** | **直接跳过**，不要写进文档占篇幅 |
| **互相矛盾** | ★ **这才是你要的**。逐条写：谁的结论 / 跟谁冲突 / 冲突点 / 你最后怎么裁的（附理由） |
| 一家独有、三家没提 | 可能是新洞察，也可能是它跑偏 → 写下来待核 |
| 都一致但你不认同 | **你的盲区** → 写下来，别假装共识就是对的 |

**实证**（第二批 v3 第 3 轮）：Qwen 说「环境快照空就 fail-fast」，GLM 说「先做对照实验」。
**分歧处正是 AI 自己也没想清楚的地方** —— 最后它用历史数据做了实验，得出两家都没说的
第三结论（「调用方依赖」）。**那个结论的价值来自分歧，不来自共识。**

**为什么要做分歧探针**：贵的时候多跑几家是为了「取共识」（贵 → 要一次拿到最可信的答案）。
免费之后该反过来 —— **跑 4 遍不心疼了，那就专挑它们打架的地方看**。

### Codex 提问：必须用 codex-visible.js（不然你看不到它在干嘛）

**问题**：`codex-run.ps1` 把输出全塞进临时文件（`-o $tmp`），**中间过程一个字不打印**。
用户看到的现象就是「问了之后一直停在那里，我根本看不到进度发生了什么东西」。
gpt-6-astra 可能跑几分钟，无人值守时这跟死机没区别。

**解法**：`codex exec` 原生支持 `--json`（JSONL 事件流），`codex-visible.js` 接上了它。

```
┌─ codex 开始  02:12:16
│ cwd=…minecraft-numen  sandbox=read-only
│ 问题: 一句话说明：为什么门禁要查实物而不只查痕迹？
│ ────────────────────────────────
│    0s │ thread.started
│   11s │ 🔀 路径: Spike（先读取规则真身，随后给出一句话结论）
│   20s │ item.started / item.completed
│   29s │ 因为痕迹只能证明"曾经做过"…
│   29s │ ✔ 本轮完成
└─ 结束 code=0  用时 31.3s
```

**看得见的四件事**：① 每行带秒数（能分辨"在动"还是"卡住"）② 它的**路径**（在干什么）
③ 逐条 item 事件 ④ 硬超时（默认 900s，超了杀子进程）
