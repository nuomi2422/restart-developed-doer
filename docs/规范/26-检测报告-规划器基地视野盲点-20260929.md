# 26 · 检测报告：规划器"基地视野盲点"（用户点名的盲点）

> 2026-09-29 自愿检测（用户休息前交办：「规划AI不知道基地里有什么方块/什么东西，
> 导致他重新规划了一遍基地的东西 —— 你自己开着检测，能不能检测到就是你的关键点」）。
> **性质：检测报告（只读发现）。未改动任何代码。**

---

## 一、结论一句话

**规划器对"基地里到底存了什么"是半瞎的**：它能看到"存了 27 种"这个**数字**，
看不到**是哪 27 种**；于是会把基地里已有的东西**再规划一遍**。
兜底目前靠**执行 AI 自己发现并 `report_task_concern` 上报**（双向协商），**不是规划器自己看见**。

---

## 二、根因（3 个叠加，均已对源码核实）

### 成因 1 · `RddAssetContext.details()` 偏好 `summary`，把 `important_items` 丢掉 ★主因
```java
private static String details(Map<String, Object> value) {
    Object summary  = value.get("summary");
    Object contents = value.get("important_items");
    if (summary == null && contents == null) return "";
    return " details=" + text(summary != null ? summary : contents);  // ← 有 summary 就不看 contents
}
```
而"基地"资产的 `value` **同时**有两者（其实有**三**者）：
```
summary          = "respawn bed; facilities=8; stored item types=27; completion=true"
important_items  = { minecraft:iron_ingot:20, minecraft:cobblestone:243, minecraft:dirt:47, ... }
facilities       = ["minecraft:crafting_table@425,75,-301", ..., "minecraft:furnace@425,75,-300",
                    "minecraft:chest@426,75,-300", ...]
```
→ 规划器**只拿到 summary**，**箱子明细 + 设施清单（含坐标）全被静默丢弃**。

> ★ **用户补充（2026-09-29）**：*"基地里明明已经有箱子、床、熔炉之类的，规划器也不知道；
> 但我看到它后来上去问（`report_task_concern`），它（规划器）肯定是知道的。"*
> → 与源码一致：`details()` **压根不读 `facilities` 字段**，所以设施清单被丢；
> 规划器只能靠**执行 AI 事后上报**才知道。**这就是"事后兜底"的实证。**

### 成因 2 · `render(registry, 1200)` 硬截断 + `break`
```java
if (out.length() + line.length() + 22 > maxChars) break;   // 超限直接停，后面的整条不要
```
资产按 `observedAt` **最新优先**排序。资产一多（实测 `rdd_assets` 有 **128 条**），
**靠后的条目（含基地）可能整条不出现**。

### 成因 3 · 不是"全瞎"（重要，避免修错方向）
单个 `kind=machine label=minecraft:chest` 的箱子资产**没有 summary** → 其明细**能渲染**。
**所以箱子内容其实部分可见**，瞎的是**基地那条聚合**、以及**被截断掉的部分**。

## 四、为什么这属于"盲点"而不是"聪明"（用户关心点）

| 现象 | 谁发现 | 代价 |
|---|---|---|
| 规划器按不存在的东西派活 | **执行 AI 事后上报** | 先白跑 6 次 `mine` |
| 规划器重采基地已有的东西 | **执行 AI 事后上报** | 白跑 + 烧重规划预算（每级只有 3 次） |

**设计上的缺口**：`report_task_concern` 是**事后**通道；**事前**规划时看不到箱子明细。
→ 正解应该是**把"基地里有什么"在规划期就给它**（而不是靠执行 AI 撞墙后上报）。

## 五、建议的修法（**未实施，待批**；按风险从低到高）

| # | 修法 | 风险 | 说明 |
|---|---|---|---|
| 1 | `details()` 改成 **summary + contents 都给**（不二选一）| 低 | 一行改动，直接补上主因；有单测可加 |
| 2 | `render` 的截断**别硬 break**：优先保证"base/chest 这类关键资产"一定进；其余按需 | 中 | 要让"基地/箱子"有保底名额 |
| 3 | 把基地摘要从"数字"改成**有上限的明细**（如 top-N 物品）| 中 | 兼顾信息量与长度 |
| 4 | 规划期显式对照"要的东西 vs 基地已有" | 中高 | 动规划逻辑，需回归 RL-1..RL-8 |

> 用户此前指示：**别影响现在这批验证、别乱动**。所以本报告**只报不改**。

## 六、我加的自动检测（"自己开着检测"）

已把这条盲点的**可检测信号**加进 `task-efficiency-watch.js`（只读，不影响任何东西）：
- 读 `rdd_status` 的目标条件（`condition.asset_key` + `minimum`）
- 读 `rdd_assets` 里基地/箱子的已知存量
- **若"目标要的量"≤"基地已知有的量" → 报 `planner_gap`**（"要的东西基地已有，规划器可能没看见"）

这样它**再犯一次就会被自动记下来**，并带上当时的坐标与数量作为证据。
