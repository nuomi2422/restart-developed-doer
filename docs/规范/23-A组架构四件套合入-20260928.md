## 三、冲突怎么解的（两处，都在 `RddPlugin.java`）
冲突根因：那份提交基于**已拆解**的版本（用 `RddAssetFacade` / `RddFactFacade` 门面），
而当前分支**没有那次拆解**（C 组没合入），所以写法不同。

**解法：保留当前分支的直调，只把新功能块加进去**——不引入不存在的门面类。
| 位置 | HEAD（保留） | 那个提交（只取新增块） |
|---|---|---|
| `onCompanionDeath` | `recordDeathLostHistory(companionId, body);` | `RddRepairDispatch.onDeath(...)` 块 |
| `bindCurrent` | `facts(...)` / `assets(...)` 直调 | `requirement_manifest` publish 块 |

> 教训：cherry-pick 冲突时**先判断"哪边是主干现状"**，再把新功能嫁接上去；
> 不要为了合入一个提交而顺手引入一整套未合入的重构（那等于偷偷合了 C 组）。
