## 四、经验条目契约（Schema）

实体 `entityType="Issue"`，`name` 用 `issue/<短名>`；observations 固定 5 段：

```

  - 关键词: 不产出, tools不变, loop_detected, 连不上, 网络, VPN
  - 场景: gpt 实例 / assist / 任务链执行
```

## 四·补 · 何时写入 / 怎么写（用户定）

**何时写（触发时机）**：
1. **吃了亏 / 踩了坑** —— 任何"本可避免"的失误（如：不产出其实是网络断；脚本被 PS 编码坑）。
2. **问题/盲点** —— 运行或写码时遇到的盲点、绕了弯的地方。
3. **相似问题** —— 觉得"以后可能还会遇到"的同类问题，主动记。
4. **关键约定/决策** —— 影响后续的约定。

**怎么写**（用当前已装 MCP 的真实工具名）：
- `memory_create_entities`：新问题 → 实体 `entityType="Issue"`，name 如 `issue/<短名>`，observations 5 段（现象/根因/解决/关键词/场景）。
- `memory_add_observations`：老问题有新进展 → 追加。
- `memory_search_nodes(query=单词)`：**先检索再注入**（子串匹配，用单关键词）。
- `memory_read_graph` / `memory_open_nodes`：看全库/取指定。

**注入时机**：每轮开始或遇异常时，用单关键词 `search_nodes` 命中相关条目 → **只注入命中的 1~N 条**（非全量）。

## 五、注入策略（定向，非全量）

1. **检索时机**：每轮/每遇异常时，O 用 `search_nodes(关键词=当前场景)`（或备选 B 语义检索）。
   - ⚠️ **该 server 为子串匹配**：用**单个关键词**（如 `网络`、`loop_detected`、`不产出`），**别用整句/多词**，否则搜不到。
   - 建议每条经验在 observations 里放「关键词: ...」一行，便于命中。
2. **只注入命中项**：把命中的 1~N 条经验贴进当前上下文（或规划请求），**绝不整库塞**。
3. **写回时机**：问题解决后 `add_observations`（现象/根因/解决/关键词/场景）。
4. **可接规划链**：命中经验可作为 `RddPlanningKnowledge` 之外的补充知识源（合适时注入）。
