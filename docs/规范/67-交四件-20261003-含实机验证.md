## 4️⃣ ★ 实机验证（今天下午新增，这是最有价值的部分）

### 4.1 ★★★ E2 首次打通：内脑主动调 `learner_intake`

**实验设计（关键）**：我只对 DDD 说「用 learner_intake 读一下候选队列」，
**没教它先调 `find_tools`** —— 验的是「它自己会不会想到去捞」。

| 判据 | 结果 |
|---|---|
内脑看到延迟工具目录 | ✓ 它的 `reasoning_content` 里自己点名了 `learner_note`/`experience_learn`/`experience_recall`/`learner_review` |
它自己调 `find_tools` 捞 | ✓ 返回 `expanded=learner_intake` |
真的调用 | ✓ `{"cursor":"0","limit":200,"max_enqueue":16}` |
`learner.jsonl` 出现 `type=intake` | ✓ 两次（08:33:14Z / 08:34:13Z）|
不只读，还照着写待办 | ✓ 两条 `type=noted`（08:34:59Z / 08:36:50Z），第二次 `find_tools` 展开的是 `learner_note` |

⇒ **结论修正**：之前说「拿不到与去拿之间的桥断了」**不对**。
桥是通的（拦截消息 + `find_tools` 都能用）。**真正的缺口是「它平时想不想起来用」** ——
一点名就会用，没人点名就不用。

★ 它还给了自己的理由：「我判断下要不要记这个卡住的问题值不值得学：这是第 3 次尝试上不来…」

### 4.2 ★ AC 状态机跑通（owner 亲眼看到效果）

用 MCP 驱动 ACX 跑 `mine_nearest_ore`（5 步）：
```
RUN_STARTED → STEP_STARTED(read) → STEP_SUCCEEDED
→ STEP_STARTED(hp_gate) → STEP_SUCCEEDED
→ STEP_STARTED(scan) → STEP_SUCCEEDED
→ STEP_STARTED(has_ore) → STEP_SUCCEEDED
→ STEP_STARTED(move) → STEP_FAILED **PAUSED**   ← 受理即 PAUSED = 真在走过去
→ RUN_FINISHED **PAUSED**
```
**ACX 从 (522.6, 64, 1350.2) 走到 (526.5, 64, 1351.3)**（约 4 格）。

另一次跑 `do_while_scan`（演示 `do_while`）：循环体真跑 2 轮，
然后 `CONTROL_MAX_ITERS status=PAUSED` —— **按 `max_iters=2` 主动停下**。
这就是状态机与「一串命令」的分界。

⚠️ 途中抓到一个**真 bug（脚本里的）**：`move` 步同时传了 `block="minecraft:iron_ore"`
和 binder 取出的坐标 ⇒ `goto` 当场拒绝（两者二选一）。删掉 `block` 就好。
**系统的报错质量很高**：把三种正确写法全列了出来。
