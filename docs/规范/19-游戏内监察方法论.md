# 19 · 游戏内监察方法论（AI 自己看自己怎么查 bug）

> 定位：`D:\rdd\docs\rdd-docs\rdd架构\自编译统一版\19-游戏内监察方法论.md`
> 缘起：用户方法论——「他干活会一段段说话自己说，长时间不说话就是卡了；说了什么奇奇怪怪的也能找出来」。
> 本文把该方法固化成**可重复、可自动化**的监察流程，并附本轮实战证据。

---

## 〇、为什么要「自己看自己」

编译成功、测试全绿、事件没报错，**都不等于它在游戏里真的干对了活**（红线：编译成功 ≠ 真实行为成功）。
AI 在游戏里干活时留下三类痕迹，监察就靠它们：

| 痕迹 | 存在哪 | 能回答什么 |
|---|---|---|
| **它说的话**（自言自语/计划/结论） | `monitor\context*.jsonl` | 它卡在哪、误解了什么、为什么重复 |
| **它做的事**（工具调用与返回） | `monitor\tools.jsonl` | 它到底动没动、工具是不是失败 |
| **世界的变化**（物品/实体/坐标） | `monitor\rdd.jsonl` + MCP 只读查询 + 截图 | 它是不是真把世界改成了目标样子 |

**核心心法**：**别用眼睛判断"它是不是在晃"，用数字判断。**

## 一、五步监察流程（每轮都是短命令，看完就汇报）

### 第 1 步：它还在动吗？（最便宜的死活判据）
```powershell
$mon="D:\rdd\mc\The Best of Twilight Forest\config\numen\monitor"
(Get-Item "$mon\tools.jsonl").LastWriteTime     # 静默多久了
```
- **判据只看 `tools.jsonl`，不要看 `ai.jsonl`**：后者有回合不代表发了动作。
  实战：昨晚 17:58→18:02 `ai.jsonl` 一直有回合，但 `tools.jsonl` 停了 24 分钟 —— AI 在「发指令却不动/闭嘴」。

### 第 2 步：它有没有在原地打转？（把横跳变成数字）
```powershell
node D:\rdd\workspace\rdd-selfcompile\scripts\sample-ai.js 14 5000
```
输出：`travelBlocks`（总位移）、`stillIntervals`（静止区间数）、`reversals`（方向反转 ≥135° 的次数）、
`distinctBuckets`/`topBucketShare`（8 格区域桶分布）。
- 实战：`travelBlocks=0, stillIntervals=12/13` → **70 秒零移动**（有指令、没身体）。

### 第 3 步：它在说什么？（**抓 bug 命中率最高的一步**）
```powershell
node D:\rdd\workspace\rdd-selfcompile\scripts\ai-talk.js 60 --suspicious   # 卡住/换路/无法 类话术
node D:\rdd\workspace\rdd-selfcompile\scripts\ai-talk.js 60 --gaps        # >45s 静默段
```
- **本轮关键 bug 就是它挖出来的**：AI 自己说「我先前直接摆在草方块泥土格上，服务器随即把它清掉了」，
  直接指出「世界资产口径 vs 背包口径」的矛盾。没有这几句，人工翻日志几乎不可能定位。
- 关键词表在脚本 `PAT` 里，可按需加。

### 第 4 步：事件层有没有自报警？
```powershell
Get-Content "$mon\rdd.jsonl" -Tail 300 | Select-String 'parked|stalled|nudge|problem|waiting'
```
关注：`subtask_parked_renudge`（催工）、`subtask_parked_silent`（催满停手）、
`parked_early_achievement`（停车但条件已达成）、`NO-PATH`（寻路失败）、
`ARRIVED-IN-PLACE`（到达判定，**要核对 feet 与 goal 的高度差**）。

### 第 5 步：亲眼看（视觉兜底，只在文本线索指不出时用）
```powershell
node D:\rdd\workspace\mc-openclaw-controller\scripts\watch-ai.js --from-rdd --scan
```
- 它会：从 Numen 取 AI 坐标 → 飞过去 → 对准 → **PrintWindow 抓无遮挡截图**。
- 顺序铁律：**先起 OpenClaw 服务器，再进 MC**（mod 只在启动时连）。
- 看图清单：装备对不对 / 手上拿什么 / 是不是在空中或墙里 / 周围有没有该捡的掉落物 / 有没有怪。

## 二、怎么把「看见的」升级成「能自动发现的」

看到一次就修成机制，才不会忘：

| 看到的现象 | 固化成的机制 |
|---|---|
| 长时间不说话/不动 | `sample-ai.js` 量化 + 停泊守望催工（1/2/5 分钟递进，满 3 次发 `subtask_parked_silent` 停手） |
| 横跳导致催工永不触发 | `parkedFingerprint`：**抗抖动进展指纹**（背包 + 8 格区域桶），坐标抖动不再喂饱窗口 |
| 条件已满足却原地罚站 | `parked_early_achievement` 事件（默认只报不动手，口径归人定） |
| 寻路反复失败 | `NO-PATH` 事件 + 退避（提交 `3b582053`，已在树内） |
| 「在树上就算到了地面」 | `GoalXZ` 垂直容差（2026-09-28 修，见 `19-游戏内监察方法论` 附则） |

**心法**：看到异常先问「这是症状还是机制？」——症状要追到机制，机制要写成测试。

## 三、坑位清单（每条都真踩过）

1. **`Get-Content` 读 JSON 会乱码**：`ConvertFrom-Json` 报「无效 JSON」常是中文被按 GBK 解读。
   **解析放 node 里做**（`oc-drive.js` / `ai-talk.js` 都已处理），PowerShell 只看数字。
2. **不要用 PowerShell 重写 Java 源码**：`Set-Content -Encoding UTF8` 会写 BOM → `\ufeff` → 整模块编译失败。
   用编辑工具改；确需重写用 `[System.IO.File]::WriteAllText($p,$t,(New-Object System.Text.UTF8Encoding($false)))`。
3. **测试结果可能是旧缓存**：编译失败时读 `build/test-results` 拿到的是上一轮结果，会误判。
   先确认 gradle 真的编译过。
4. **实体扫描会丢目标**：AI 走出客户端跟踪范围后 `getVisibleEntities` 里没有它 → 改从 Numen `get_self_status` 取坐标。
5. **游戏内 `screenshot` 动作是空实现**（返回 `screenshot_not_implemented`）→ 用 `PrintWindow` 抓窗口。
6. **窗口会被 OpenCode 挡住**：`CopyFromScreen` 只能抓可见部分；`PrintWindow(...,2)` 能抓被遮挡窗口。
7. **别只信一个信号**：坐标不动 + 有指令 = 身体任务卡死；坐标不动 + 无指令 = AI 闭嘴；两者病因不同。

## 四、每轮监察的汇报格式（给人看的，别刷屏）

```
状态：sub/prim/条件/assets 一行
动没动：位移 X 格 / 静止 N 区间 / 反转 N 次
它说了：可疑话术 1-2 条（原文）
事件：parked/NO-PATH 等异常计数
看图：（只在有视觉发现时）一句话
判定：新增 bug / 复现 / 修好了 / 需要人拍板
```

## 附则：2026-09-28 本轮修掉的「在树上就算到了」

- 现象：`goto` 只给 x+z（COLUMN，契约写「Y 解析到地表」），但 `GoalXZ.isInGoal()` **完全不看 Y**
  → 站在丛林树冠 y=62 对 y=47 的地面目标直接判「已到达」（日志 `ARRIVED-IN-PLACE feet=425,62,-305 goal-center=424,47,-301`）
  → 「到了」→被派下一个相邻目标 → **原地左右横跳且永不完成**。
- 修法：`GoalXZ`/`NavGoal.Column` 加**可选垂直容差**；COLUMN 目标把解析出的地表高度传进去（±2 格）。
  未给容差的调用方（内部列追踪等）行为**逐字不变**。
- 契约测试：`GoalXZVerticalToleranceTest`（5 条，含负容差钳位、负坐标、老语义不变）。
- 证据：`:core:common:test` **332 绿**；三模块全量 **617 绿 / 0 失败**（无能力回退）。
