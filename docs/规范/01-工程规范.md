# 01 · 工程规范（优先）



## 一、先分类（三档，只升不降）

| 档 | 范围 | 谁写 | 谁审 | 门禁 |
|---|---|---|---|---|
| 工具级 | 单工具/局部脚本/文档修正 | 免费 AI 自主 | 测试记录必写 | 面向行为验证 |
| 模块级(Bounded) | 心跳/看门狗/双实例/Bridge/Harness/自编译子模块 | 外脑池参议 + 免费执笔 | 外脑 + 交叉审 | 工作流文档先行 |
| 架构级(Architectural) | RDD 核心 / 跨模块契约 
/ 生产安全 / 自变异控制边界 | **留人工待批** | 人工 + 多模型评审 | 完整九步流 + 用户批准 |
> 起步第一行自报路径与档位；写码前停下等批准（架构级）。发现隐藏复杂度只能升档。

## 二、九步流（内置九规范）

1. 先分类（上表）。
2. 改接口**先查消费者**，接口变更必须**契约回归**。
3. 首测通过后立即补**边界/异常/极端/多数据**测试；高风险补**压力测试**。
4. 关键路径同步埋 debug（入口/输入/分支/输出）。**★ 埋点先行**：架构期推演出的边界风险，**默认先埋探针+统一记录**（第八系统独立日志区），真命中再写最小修复——别停在架构期把所有防护都写出来（见 `13` §五；红线/生死/安全路径除外，仍须预先防护）。
5. **编译成功 / MCP 返回 OK ≠ 真实行为成功** → 看真实世界证据。
6. **按模块 commit + 标注**，保留**单模块回滚点**；连续两次失败找不到根因 → 止损。
7. 固化闭环必须含**测试 + 日志 + 事实证据**；无证据不宣称完成。
8. 写完代码同步写**解释性维护说明**（改了哪/为什么/怎么调/依赖/入口出口）；后续变更同步更新。
9. **主要功能不回退**：重构/拆解/搬迁前对照「不回退清单」；破线立即回滚。

## 二·补 · 写代码工程规范明细
写代码时**这些规范缺一不可**：

| 规范 | 说明 | 落点 |
|---|---|---|
| **模块化回滚** | 按模块保留可回滚版本（**要实装**，不只靠 git）| 见 `11-模块化回滚.md` |
| **边界测试** | 边界/异常/极端/多数据 | §三.3 |
| **压力测试** | 高风险路径高压（连续 tick/空背包/坏 JSON/并发） | §三.3 |
| **回归测试** | 单元/模块 `--rerun-tasks` + 契约对账 | §三.1/2 |
| **契约测试** | 接口/事件名/工具名/schema 变更前后查消费者 + 对账 | §三.2 |
| **运维文档** | **非常重要** —— 让接手者/运维一看就懂怎么跑、怎么修 | 每模块维护说明（第 8 条） |
| **代码转文档** | 把代码/链路讲清（数据流、入口出口、依赖），方便查看与运维 |存 "D:\rdd\extras\rdd自编译"` |

> 运维 > 功能：功能能跑但没人看得懂 = 负债。每写完一块，**同步产出「怎么运行/怎么看/怎么修」**。

## 三、三类回归（每次改动必跑）

1. **单元/模块回归**：`gradle :rdd-core:test :plugins:rdd:test --rerun-tasks`，期望全绿（基线 `rdd-core 207/0`、`rdd 92/0`）。
2. **契约回归**：动接口/数据契约（字段/事件名/工具名/schema）前先查消费者；变更后 `monitor/rdd.jsonl` 事件与 `rdd-tasks/*.json` 状态**必须对得上**。
3. **边界/压力回归**：边界/异常/极端/多数据 +（高风险）连续 tick、空背包、坏 JSON、并发协商。


## 五、门禁铁律

- 编译成功 ≠ 行为成功；MCP 返回成功 ≠ 世界真实改变。
- 未 VERIFIED 不部署生产；部署生产前先 commit。
- 每次变更按模块 commit，保留单模块回滚点，通过后 push。
- 偏离方向连续两次失败且找不到根因 → 止损汇报。
- Kill Switch（多实例串台/证据链缺失/绕过生产门禁）→ HALTED。
- **长驻/后台进程一律"脱离启动 + 短命令轮询"**（起游戏、起监测台、起看门狗都算）。
  直接等它返回会把 shell 卡死，而进程其实已经正常跑起来了 —— 加长 timeout 只是等得更久。
  正确写法见 `12-进游戏验证工具集.md` §2.0。
  **★ 但「脱离启动」不等于 `Start-Process`** —— 会被调用方的 shell 回收，见下方 §五·补。

## 五·补 · 写码链踩坑实录（2026-10-02 实测，每一条都真死过一次）

> 这不是理论。以下每一条都是本轮实际损失了几十分钟才定位到的。**任何人写 Java 改 Numen 都会踩到同样的坑**，所以放在这里而不是放在某次会话的记录里。

### A. 编译会静默死亡 —— `Start-Process` 拉起的进程树会被调用方 shell 回收

| 症状 | 真相 |
|---|---|
| `phase-build.log` 停在某个 task 名（如 `> Task :api:neoforge:compileJava`），**无任何错误行**，每次字节数**完全一致**，18~42 秒后 java 与 wrapper powershell **一起消失** | **不是** OOM、不是崩溃、不是代理、不是磁盘。**是 `Start-Process` 拉起的进程树在调用方 shell 结束时被一起回收**。无 `hs_err_pid`、无 WER、无 System 2004/2019 资源事件 —— 因为根本没有崩溃，进程是被正常终止的 |

**正确写法（编译一律走这个）**：

```powershell
$t = Get-Date
schtasks /delete /tn rddbuild /f 2>&1 | Out-Null
schtasks /create /tn rddbuild /tr "powershell.exe -NoProfile -ExecutionPolicy Bypass -File `"<wrapper.ps1>`"" /sc once /st $t.AddMinutes(2).ToString("HH:mm") /f
schtasks /run /tn rddbuild
```

实测：改成计划任务后构建从「必死 18~42 秒」变成「活过 190 秒并 BUILD_OK」。
起游戏同理（`tn rddmc`）。**短任务（<30 秒）用 `Start-Process` 没事。**

### B. ★最坑的一条：编译错误与「进程被杀」表现完全一样

`rdd-selfcompile\scripts\build-jar.ps1` 用 `*> $logFile` **吞掉 Gradle 全部输出**（含 javac 的 `error:` 行）。
进程一死，缓冲区全丢 ⇒ **javac 的编译错误一行都留不下**，日志就停在 task 名上，和被 kill 一模一样。

**判据（三条同时成立就是编译错误，不是被杀）**：
1. `phase-build.log` 停在某个 task 名上
2. 里面**没有一行** `error:`
3. `jar/` 和 `deploy/` 目录**全空**

**定位手法：回退改动做二分** —— 先把改动最大的那个文件退回 `.bak` 重编。
本轮就是这样：退掉 `EntityAgentLoop.java` 一个文件 → 立刻 `BUILD_OK`，真凶当场现形。
**比查代理 / 内存 / 事件日志快得多**，那三条全查过了，都是无辜的。

> ⚠ 想根治要改 `build-jar.ps1`（让 javac 错误进 stderr 而不是被 `*>` 吞掉）。
> 那是 `scripts\` 目录改动，**要用户批准**，至今未改。

### C. 本轮两个真编译错误（都是「凭直觉写了不存在的东西」）

| 错误 | 真相 | 教训 |
|---|---|---|
| `CompactSplit.estimateTokens(t.content())` | 只有 `estimateTokens(ConvoState.Msg)`（`:117`）和 `estimateTokens(List<Msg>)`（`:189`），**没有 `String` 重载** | 新写调用前**先 grep 目标类的全部 public 静态方法签名**，别按直觉推断重载 |
| `ToolDisclosure.slimExpanded` 声明成包级私有却被跨包调用 | `EntityAgentLoop` 在 `com.dwinovo.numen.client.agent`，`ToolDisclosure` 在 `com.dwinovo.numen.agent.tool` | **同一个文件里的方法一个写 `public` 一个忘写** → 加完新方法**逐个核对可见性** |

### D. 验 jar（不信 `DEPLOY_OK` 一句话）

- **必须 `javap -v` 查常量池。** `javap -c` **看不到 `+` 拼接的字符串** —— 编译成 `invokedynamic makeConcatWithConstants`，recipe 不在 `-c` 输出里。本轮用 `-c` 验证过一次，**误报「NO NEW STRINGS FOUND」**。
- **JDK 有两个位置，别搞混**：编译用 `gradle.properties` 的 `org.gradle.java.home=D:\rdd\tools\jdk21\jdk-21.0.11+10`；而 **`javap` / `jar` / `java` 命令在 `D:\bin`**。
- **解 jar 必须保留包目录结构**（解到 `<dest>/com/dwinovo/...`），压平会**静默无输出**。

### E. 一个模块一个 wrapper

`run-mutation.ps1` 结束时 `exit` 会**把 wrapper 脚本一起带走** —— 想用一个 wrapper 串跑 `api:neoforge` + `plugins:rdd` 的话，第二个**永远不会执行**，日志只到 5 行。**一个模块一个 wrapper 文件。**

### F. 代理 7897 挂了 = Gradle 静默死亡

`rdd-selfcompile\scripts\config.ps1:16` 的 `GRADLE_OPTS` 把 Gradle 流量强制走 `127.0.0.1:7897`。
Fabric Loom 走到 `rebuilding loom cache` **必须联网**，代理一挂就死得毫无征兆。
**wrapper 脚本开头第一件事就是查 7897 在不在**，不在就 `exit 2` 并打印 `PROXY_DOWN_ABORT`。

### G. 内存：本机只有 7,916MB

游戏进程本身占 **1,753MB**，`gradle.properties` 是 `-Xmx3G`。**游戏和编译不能同时跑。**
编译前先优雅关游戏（`CloseMainWindow()` → 等 12s → 必要时 `Stop-Process -Force`）。
调 `-Xmx` 之前**先备份 + 加版本标记注释**，且记得**用完还原**。

### H. 判游戏活没活（`launch-mc.ps1` 的判据不可信）

- `launch-mc.ps1:24-25` 用 `Get-CimInstance` 按命令行匹配判「已在跑」，而 **WMI 在这台机器上时灵时不灵**（实测 `0x80041032`）→ 会报 `running=1` 而实际没进程，白等一轮。
- **`LAUNCH_OK` 是假阳性**：`launch-mc.ps1:49` 只 `Start-Sleep -Seconds 3` 就打印，证明的只是「cmd.exe 起来了」。
- **正确判据**：`Get-Process java,javaw` 看 **pid + `StartTime`**（比时间戳是否更新），再确认 **MCP 8765 在 LISTEN**。
- **崩溃只写 stderr**：`latest.log` 在崩前一刻**无声截断、零错误行** —— 「日志没异常」≠ 没崩。真相在 `rdd-selfcompile\mutations\launch-gpt.log.err`。
  （本轮一个第三方 mod `Flashback-0.39.7` 的 ImGui 断言崩溃就是这么抓到的，两次 `.err` 文件大小一字不差 = 确定性崩溃。）

### I. OpenClaw 8080 **必须在游戏之前起**

mod `client_controller 1.0.2` 启动时连 `ws://127.0.0.1:8080/minecraft`，连不上就**不重连**
（日志说「将持续重连」但**再无重连记录**）。观察者装备没画面就是这个原因。
**起游戏前先 `Get-NetTCPConnection -LocalPort 8080 -State Listen` 确认。**

### J. 写 `.ps1` 和跑命令的四个坑

| 坑 | 症状 | 对策 |
|---|---|---|
| **`.ps1` 无 UTF-8 BOM** | PS 5.1 读中文 → 语法错 → 表现成「`Start-Process` 喊 launched，但进程压根没起来、日志文件连创建都没有」 | 写完立刻查头三字节 `239,187,191`，没有就 `[System.IO.File]::WriteAllBytes($p, $bom + $bytes)` 补上 |
| **`Start-Process -ArgumentList` 拆空格** | `-Requirement 'a b c'` 里的空格把后面的词变成无名位置参数 → `run-mutation.ps1` 参数绑定失败直接退出 | 整段包成 `.ps1` wrapper 再 `Start-Process`，引号写在**文件里** |
| **内联 JSON 被 PS 引号拆坏** | `node -e "…"` / 传 JSON 参各种诡异报错 | 一律写 `.js` 文件用 `execFileSync(NODE, [CLI, ...args])` 传 argv 数组；`numen-mcp.js call` 只吃 a1/a2，`companion` 必须**写进 JSON 里** |
| **清僵尸进程会杀掉自己** | `Where-Object { $_.CommandLine -match 'restart-mc' }` 匹配到 Bash 工具自己的 shell（同句里后面的起游戏没执行） | 加 `-and $_.ProcessId -ne $PID -and $_.CommandLine -match '-File'` |

### K. 埋点数据读之前先看结构，别猜字段名

**没有 `usage` 对象**，且 `excluded: ["credentials","hidden_reasoning"]` → **埋点故意不记 reasoning 内容，只能算残差**。

### §五·补二 · 观察者纪律：别把别会话的架构当自己的（2026-10-02 用户纠偏）

> 出处：用户原话「根本就不能让mcp直接去外部AI操控游戏的AI去帮他完成任务」「你在说什么啊」
> **本工作区没有「外部 AI 驱动游戏」这条线。** 看到自己汇报里出现这个说法 = 已经跑偏。

**三层职责（写死，不可越位）**

| 谁 | 干什么 | 禁止 |
|---|---|---|
| 游戏内 AI（RDD） | **自己动**：接任务→规划→用工具干活 | 观察者不得越位替她干活 |
| 我（OpenCode） | **观察者**：视觉锁定（OpenClaw 8080，只动玩家相机绝不动同伴）+ 监测台 8776 + `latest.log`/`rdd.jsonl`/`context.jsonl` → 看到问题→改代码→重启→再看一遍 | 不越过「只走 `run-mutation.ps1` 改码」 |
| MCP 8765 | **只是 poke 工具**，验证时**按工具名直接调** | **永远不枚举（不用 `tools/list`）** |

**MCP 正确用法**：`numen-mcp.js call <tool> <json>`，`companion` 写进 JSON 里（CLI 只吃 a1/a2 两个参数，写成第三个参数会被丢掉）。
**验证闭环靠世界证据**（看 RDD 实际做了什么 + `rdd_status` 判定翻转），**不靠 BUILD_OK**。

**★ 报 bug / 提议动手前必过两道闸**

1. **闸一「我们用不用」**：报一个 bug 前必须先答「这个接口我们这条线用不用」。**不用 → 降级成待办记一行，不占主线、不主动提议修。**
   （2026-10-02 反例：把从没用过的 `tools/list` 报成「卡住主路」，浪费用户时间）
2. **闸二「不修挡什么」**：提议修任何东西前必须能一句话答出「不修会挡住我们什么」。答不上来 → 不修，先问用户。

**★ 三条防跑偏**

- 用户转贴别的东西（别的会话方案/别人报告/网页）时，**先问「这是给我的任务还是你正在看的资料」**。**用户转贴 ≠ 派活。**
- **不要因为途中发现新东西就自己扩范围开新主线。** 用户说「收工了」就收工。
- **每次汇报必须让用户清楚知道三件事**：这一轮改了什么 / 现在在干什么 / 要不要花他的时间。

**★ 本轮四个浪费点（都写进记忆图谱了，别重犯）**

1. **砍 token 砍掉了执行能力** —— 把原作者写的工具目录摘要 96→40 字，59 行里 42 行变半句话，AI 判断力下降。已全部回退 + 立 RL-21。
2. **一个轮次没跑过测试** —— 最后跑门禁才发现破坏 3 条既有守护测试。**`BUILD SUCCESSFUL` 只证明能编译，测试才证明没破坏东西。**
3. **两次结论自我推翻**（先说省 19% 实为 0% 略负；先说压缩在烧钱、实为自动压缩永不触发）—— **都是下了结论才去查。**
4. **编译静默死亡排查耗掉几轮**（详见上方 §五·补 A/B 两条）。

**★ 四条准则**：先量后下结论 · 先跑测试后宣布成功 · 先确认归属再动手 · 不中途自己扩范围。
