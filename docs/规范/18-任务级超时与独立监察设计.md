## 二、根因（已定位到代码行）

**根因不是寻路，是「进展判据」被抖动的坐标污染。**

1. `RddParkedWatcher` 判断「有没有进展」用的指纹 = **背包 + 精确坐标**
   （`RddStallWatcher.fingerprint()`，第 162-165 行）。
2. AI 在两点之间横跳 → 坐标每 tick 都变 → `!w.fingerprint().equals(fp)` 成立
   → **「无进展」窗口被无限重置** → 催工**永远不会触发**。
3. 于是形成闭环：**横跳 → 催工不触发 → 没人拍醒 → 继续横跳 → 任务永不完成**。

即用户看到的「它一直重复走、也没人管」，**横跳既是症状，也是催工失效的原因**。

### 本轮已修（已测）
- 新增 `RddStallPolicy.parkedBucket(x,y,z)`：坐标量化成 **8 格粗桶**。
- `RddStallWatcher.parkedFingerprint()`：停泊守望专用指纹 = 背包 + 粗桶。
- 区域内抖动/横跳**不再重置**窗口（照常催工）；只有真换 8 格区域才算新进展。
- 卡死检测路径**仍用精确坐标**（走路本身算进展，不误伤正常寻路）。
- 回归测试 `parkedBucketAbsorbsJitterButSeparatesRealTravel` 锁住该行为（含负坐标 `Math.floorDiv`）。
- 催工节奏改 **1 分钟 → 2 分钟 → 5 分钟递进**，3 次后彻底停手只发 `subtask_parked_silent`（不烧钱）。
- 证据：`rdd 93 测绿 / 0 失败`，`BUILD SUCCESSFUL`。
- **注意**：本轮改动**尚未部署到 MC、尚未实机验证**（用户要求先睡）。

## 三、用户要的「通用解除方法」（本文件重点）

用户原话要点：
- 「要找一个通用的解除方法，从根本上解决」
- 「监察的时候，他监察的步骤是**动没动**」
- 「根据这个**任务的难度**，给一个**超时**」
- 「如果说超时了之后，就根据任务难度、耗时预测要花多长时间」
- 「两个都可以触发」——即**任务内的自监察** 与 **外部独立监察** 各自都能独立触发
- 「这种东西根本就不是我们的问题，是它自己 AI 自己的问题」→ 监察必须**不依赖 AI 自觉**

### 3.1 两条互相独立的触发器（都要有）

| 触发器 | 归属 | 依赖 AI？ | 作用 |
|---|---|---|---|
| **A. 任务内自监察** | 执行 AI 自己在每次回合前自查 | 依赖 | 提醒它「你这任务超时了，换条路/换材料/换工具，别原样重复」 |
| **B. 外部独立监察** | 引擎侧（Detector/看门狗），不经过 AI | **不依赖** | 无进展到点就发事件 + 拍醒/换策略/上报，**AI 不配合也照样生效** |

**红线**：B 为主，A 为辅。**不得让任务完成与否取决于 AI 自己有没有反省。**

### 3.2 监察判据：看「动没动」，但要抗抖动

分三层证据，任一变化即算「有进展」（避免误杀正常慢活）：

1. **资产层**：背包计数变化（最硬，优先级最高）
2. **空间层**：离开当前 8 格粗桶（`parkedBucket`）—— 已实现，专治横跳
3. **动作层**：身体任务 `body.describe()` 变化 / 新工具调用

**反面教训（写死进规范）**：空间层**禁止**用精确坐标做「无进展」判据，横跳会把它喂饱。

### 3.3 超时按任务难度给（不是固定值）

给每个二级任务算一个**预算**（`timeout`），按难度分档，而不是一刀切：

| 难度档 | 判据（建议初值，实测再调） | 超时动作 |
|---|---|---|
| 简单（采集/搬运/进食） | 计划耗时的 3 倍 或 ≥2 分钟 | 拍醒一次（换路径） |
| 中等（挖矿段/合成链/建造） | 计划耗时的 4 倍 或 ≥6 分钟 | 拍醒 + 换材料来源/换工具 |
| 困难（找据点/多层结构/远距离） | 计划耗时的 5 倍 或 ≥12 分钟 | 拍醒 + 允许重规划该一级 |
| 任意档：连续 3 次仍无进展 | — | 发 `subtask_stuck_problem`，**交人工/外层接手**，不再烧模型 |

- 计划耗时来自 Stage-B 展开时写的估算（规划 AI 侧产物），**取不到就退回按难度档默认值**。
- 预算**按二级任务各自计**，不按一级目标整体计（否则长链里一个慢点会拖死全链）。

### 3.4 巡路横跳作为独立信号

横跳是「寻路到不了目标」的**独立故障模式**，不该混进通用超时里：

- 判据：同一 8 格桶内**反复进出** ≥N 次，或两个桶之间往复 ≥N 次。
- 动作：**判定路径不可达** → 换目标点 / 换寻路模式 / 直接上报，别再原地磨。

  改完 Java 文件务必用 `[System.IO.File]::WriteAllText($p,$t,(New-Object System.Text.UTF8Encoding($false)))`，
  或用编辑器工具改，**不要用 PowerShell 重写源码**。
- 读测试结果 XML 时注意**旧缓存**：编译失败时读到的 `test-results` 可能是上一轮的，会误导判断。先看 gradle 有没有真编译。
