## 〇 · 一句话结论

**第二批的文档比第一批更危险：第一批的文档说「没接」，第二批的文档说「已接 / 全通 / ✅」，而实机证据不支持其中四条。**
最典型的一条：`63` 让人读 `monitor/acx.jsonl` 的 `type=run_finished` + `status=SUCCESS` 判 AC 成功 ——
**实机 2450 行里 `type=run_finished` 是 0 行**（真实键是 `type=acx_event` + `data.kind=RUN_FINISHED`）。
照这句话写消费方，第一步就取不到数，然后会把「0 条」读成「从没成功过」。

### 审计口径（三条，不守这三条就会重犯 2026-10-03 那次假账）

| 层 | 含义 | 判定上限 |
|---|---|---|
| **存在** | 类/方法/字段在源码里 | 只能判 🟡 |
| **接线** | 生产代码里有人调它 / 注册它 | 只能判 🟡 |
| **实机证据** | jsonl / 日志里有它的输出记录 | 才配 ✅ |
