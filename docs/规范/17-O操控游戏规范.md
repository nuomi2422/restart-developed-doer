# 17 · O 操控游戏规范（进游戏能做什么 / 规则）

> 用户陆续给点，**本文持续补**。定位：**External Game Validator** 的操作规范（O 控客户端玩家 + 视觉）。
> 底座：OpenClaw 控制器（`oc-drive.js`，控**客户端玩家**）+ `mc-screenshot.ps1`（截图给 O 看）；**走客户端 mod，不经 Numen MCP → 同伴 AI 照常跑（共存）**。

## 一、O 进游戏后能做的（能力）

| 能力 | 手段 |
|---|---|
| 控制玩家移动/视角 | `oc-drive keyDown/keyUp/moveMouse/setRotation/lookAt` |
| 观察玩家/世界 | `getStatus / getVisibleEntities / getTargetedBlock` |
| 交互 | `click/mouseDown/up/scroll/selectSlot/typeText` |
| 视觉 | `mc-screenshot.ps1` 截游戏窗口 → O 读图 |
| 换角度 | （可经 `/gamemode spectator` + `/tp`/`/spectate`，或以 OpenClaw 移动） |

## 二、用户定的点（持续补）

1. **视觉找 bug（黑盒）**：O 可用「看画面」**像人一样找 bug**——看世界/看同伴实际做了什么，不读 RDD 内部状态。
   - 适用：粗粒度"有没有"（工作台/床/箱子/基地是否真存在）。
   - 不适用：**精确数值**（附魔等级/耐久/药水剩余时间）→ 应查**游戏内数据**（命令/F3），别指望截图看清。
2. **自建环境（创造模式）**：O 可直接**搭建任意测试环境/场景**（想搭啥搭啥），或**给同伴东西**（装备/材料/食物）、**传送到它旁边**观看、切**观察者模式**、**附身**（贴身跟随看它 POV）。
   - **观察者模式 ↔ 创造模式 来回切**最方便：**哪里卡了，就切到观察模式，用视觉看究竟发生了什么**。
   - 用途：造受控剧本（给装备验证、清背包验证、搭基地验证）、近距离复现 bug、多角度观察同伴行为。

## 三、边界与纪律

- **创造模式**：无死亡代价、无资源消耗 → **不需 RiskGate**（风险门管的是生存模式"值不值得冒险"）。
- **不替代 `verify.ps1` 正式流水线**，**不混入正式证据链**（=把"自己开创造模式肉眼看一遍"外包）。
- **控客户端玩家**（OpenClaw），**不干扰同伴 AI**；不用 Numen MCP 的驱动类指令去"替它干"。
- 视觉是**实物证据**（屏幕上真渲染出的东西），非"自我陈述"；但仍有"看不准细节"的风险 → 精确项查数据。
- 用户在场要亲看时：**O 让位，不控游戏**。

## 四、用法速查

```powershell
# 1) 起服务 + 起带 mod 的 MC
node E:\restart developing doer\mc-openclaw-controller\scripts\server.js
# 2) O 发命令
node ...\oc-drive.js getStatus
node ...\oc-drive.js lookAt "@lookat.json"     # {"x":..,"y":..,"z":..}
node ...\oc-drive.js setRotation "@rot.json"   # {"yaw":..,"pitch":..}
# 3) 视觉
powershell -File ...\mc-screenshot.ps1 -Foreground -OutPath shot.png
```
