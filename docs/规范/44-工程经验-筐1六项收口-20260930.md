## 四、怎么调的（工程规范第 8 条之三）

### 4.1 三条硬约束（违反任何一条都会出更坏的错）

1. **`rdd-core` 不碰 IO**：只给 `snapshot/restore` 数据契约，`Path`/JSON 一律在插件侧。
   反向依赖会让纯 JVM 模块长出 Minecraft 依赖。
2. **必须先 `restore` 再 `record`**：`ensureLedgerLoaded` 用 `LEDGER_LOADED` 一次性 guard。
   反过来会用旧账覆盖本次运行刚记的死亡 → **假"没死过"，比丢账更坏**。
3. **`nextSeq` 语义 = "下一次 record 将用的 seq"**（不是"已用最大值"），内部 `SEQ = nextSeq - 1`。
   seq 是批次身份，撞号 = 判据串批。

### 4.2 默认行为逐字不变，新语义显式 opt-in

`mode` 缺省 = `hold`（两参重载完全没动，测试逐条断言与显式 `hold` 等价）；
`${session}` 只在配置值**含该字面符**时替换，未含则一个字节不动（16 个 provider 零影响）。

### 4.3 刻意**不做**的事

| 不做 | 理由 |
|---|---|
| 引入 `0.8` 之类回收法定比例 | 未经验证的策略常数。本轮只把"任意一件"换成"逐项核对"，比例策略要单独一批有实机数据再定 |
| 把 `RiskGate` 接进死亡路径 | `RiskGate` 是"能不能进高风险维度"的前置门，与"复活后先去哪"不是同一件事，硬套会让"补血吃饭"被判成高风险而卡住。真正的自我保护前置 = **改变恢复决策顺序**，已由 `repeatDeath` 分支实现 |
| 真跨维度复活 | `Companions.respawnDead` 在主人所在维度复活是**明确设计**（注释 "covers dimension follow"）。同伴独自穿门 → 门框不完整时卡虚空/维度困死 |
| `condition_groups` | 功能债，不影响正确性 |

## 七、经验提炼（本轮最值钱的部分）

### 7.1 实机抓到 3 个真缺陷，单测全绿都没抓到

| # | 缺陷 | 为什么单测抓不到 |
|---|---|---|
| 1 | `repeatDeathWithin` **自匹配** | 纯函数单测每次从空台账开始，构造不出"台账里已含本次死亡"这个时序 |
| 2 | 死亡瞬间**只读 body 返回空** | 需要真实实体处在"刚死、物品栏已被引擎处理"的状态，纯 JVM 造不出来 |
| 3 | `MutationCompiler` **诊断字符集解错** | 依赖本机 locale（GBK），构造不出"javac 吐 GBK 字节"这个前提 |

> **纪律**：凡判据依赖宿主状态的代码，单测只能证明**函数对**，证明不了**被调用时拿到的数据对**。

### 7.2 三个缺陷是同一族

> **"看起来对"≠"接对了"**：①判据读到了含自己的集合 ②判据读到的数据是空的 ③解码读到的字节用错字符集。
