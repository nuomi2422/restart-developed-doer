## 二、三个设计约束（照外部评审的「防翻车」建议）

### ① 独立进程，不能挂在主循环里

> 「如果主循环死锁了，它自己的计时器也会失效。独立的看门狗才能强制打断。」

`stage-heartbeat.js` 是**独立 Node 进程**，由 `stager-heartbeat.bat` 脱离启动。
主循环死 → 它还活着。

### ② 强制**回答**，不是强制**提问**

> 「不要只让系统『问』它，一定要强制它『答』。」

关键设计：**应答是一个命令，不是 prompt。**

```powershell
node "D:\rdd\workspace\stager\bin\stager.js" hb-ack ^
  --status <ok|looping|blocked|waiting_user> --elapsed <N>m --next "<下一步一句话>"
```

**为什么必须是命令**：prompt 无法验证，命令可以。ack 落盘到
`stager\.stager\heartbeat.json`，`ctx` 和 `check` 都能看见「本阶段答过没有」。

**这跟 `mark` 是同一个思路：能被查的才叫门禁。**

四个 status 的语义：

| status | 含义 | 看门狗的反应 |
|---|---|---|
| `ok` | 在有效推进 | 静默 |
| `looping` | **自己发现**在打转 | 下一档强制自检 |
| `blocked` | 技术卡住 | 该写状态报告了 |
| `waiting_user` | 该等用户拍板 | 写完报告就停，别硬扛 |

### ③ 阶梯式干预，不一刀切

复杂 bug 确实要时间，直接掐断会误杀。

| 档 | 时机 | 做什么 |
|---|---|---|
| **SOFT** | T+预算 | 温和提醒：核对「①越权了吗 ②阶段目标达成了吗 ③状态打勾了吗」+ 要求答心跳 |
| **HARD** | T+预算+10 | **强制自检**：停下当前操作，先答「为什么超时 / 卡在哪 / 要不要用户决定」 |
| **ROLLBACK** | T+预算+20 | **自动快照** + 给二选一：<br>A) `stager loop` 回计划重排<br>B) 判定仍在推进 → 再放宽 20 分钟 |

**ROLLBACK 档只记不自动轮回** —— 自动 `next` 会毁掉当前轮的工作，让 AI 自己决定。

## 五、看门狗靠什么"看见"AI 卡住了

不是靠猜，是靠**读 `history.jsonl` 里最后一个「进入本阶段」的时间戳**：

```
阶段起点 = 最后一条 ev∈{next,start} 且 to==当前阶段 的 ts
已耗时   = now - 阶段起点
```

所以**只要 AI 用 `stager next` 推进，计时就自动归零** —— 不依赖额外埋点。

## 六、边界（重要）

| 边界 | 说明 |
|---|---|
| **注入 = SendKeys 抢焦点** | 复用了 `every-10min-drive.ps1` 的机制。**会短暂抢焦点**（和那个看门狗一样的代价） |
| **抢不到焦点就跳过** | 记日志 `INJECT-SKIP`，下轮再试。**不硬来** |
| **注入文本带前缀** | `[HEARTBEAT …· 不是用户指令]` —— 见到这个前缀的 AI **不得当成用户指令执行**（与 watchdog 的既有纪律一致） |
| **不读 AI 的对话内容** | 只读 stager 状态 + history。**不解析 AI 说了什么** |
| **不做内容判断** | 它只管「多久了」，不管「干得好不好」。质量判断是门禁和评审的事 |
