## 三、钱到底花在哪（回答「什么消耗最多」）

严格 A/B 基线：**中位 8,611 est tok / 请求**（245 条 `llm_request`，同一模型 deepseek-v4-flash）。

| 组成 | est tok | 占 | 随干活变化? |
|---|---|---|---|
| **`tools[]` 11 个常驻工具的说明书** | **3,072** | **35%** | **永不，每次照发** |
| system prompt（人设 + 行为规则 + 工具目录） | 3,033 | 35% | 永不 |
| `runtime_state`（背包 / 当前任务 / 地图笔记） | ~900 | 10% | 半 |
| 历史流水 | ~2,600 | 20% | 已限流 |
| └ 里面 RAW 的 `find_tools` 展开块 | 0 ~ 4,260 | — | 波动最大 |

**最离谱的单笔**：`build` 一个工具的说明书 = **8,657 字符 ≈ 2,164 tok = 单次请求的 25%**。
拆开：`description()` 约 2,500 字符（25 行散文）+ **21 个参数**的 schema 约 6,100 字符。
**一个工具的说明书比 AI 全部聊天记录（2,600）还长。**

> ⚠️ `llm_response` 埋点里 **没有 `usage` 对象**且 `excluded:["credentials","hidden_reasoning"]` → completion 只能算残差 `totalTokens − promptTokens`；`llm_request` 里**没有 `promptTokens` 字段** → 上面是自估。绝对值不可信，**比例可用**。

## 四、我做了什么错事（5 刀砍上下文，其中 3 刀是「把原文截短」）

上午那轮为了省钱改了 5 处。按用户新立的标准复盘：

| # | 改法 | 判定 | 理由 |
|---|---|---|---|
| ① | `<carry>` 标签去重（`RddPlugin.java:371` 删重复的 `carryHint`） | **保留** | 删的是**字面重复**，不丢任何信息 |
| ② | `ToolDisclosure.SUMMARY_MAX` 96 → **40** | **★回退** | 工具目录 59 行里 **42 行被截成半句话**（`build "Construct or clear blocks as ONE backgr…"`） |
| ③ | `SkillRegistry` 技能目录 description 截 200 字 | **★回退** | 实测只省 51 tok（占 0.6%），却截断了 skill 的触发条件 |
| ④ | `renderInventory` 背包只留 20 种 | **★回退截断，保留排序** | 实测背包 27 种被砍到 21，**藏了当轮任务要用的料**（andesite/calcite/tuff）。「按数量降序」不丢信息，保留 |
| ⑤ | `harnessHints` 11 条执行提示按任务关键词筛到 7 条 | **暂不动** | 这 11 条是**用户自己 2026-09-26 手写**的笔记（见类 javadoc），不是原版 Numen 的东西 |

### 刀 ② 的代价是隐形的、且是可测的

`SUMMARY_MAX` 40 的直接后果（`dump-catalog.js` 实测）：
```
目录 3,036 字符 / 59 行 / 其中 42 行带省略号（71% 被截成半句话）/ 每行 med=52 max=64
build                 "Construct or clear blocks as ONE backgr…"
craft                 "Craft an item from materials in your in…"
report_task_concern   "对当…RDD 任务链命令结构化回执，与指挥…"
```
**这张目录的唯一职责就是让 AI 决定「要不要展开这个工具」。** 说明变半句话 → AI 看不懂 → 猜错 → 多展开几个 → 每次多几千 token。**省下的 463 tok，被「多展开」按倍数赔回去。**

**但我当时证明不了**（诚实记录）：
1. `context.jsonl` 的 245 条 `llm_request` **全是 10-02 当天的**，改前的记录被轮转清掉了 → 做不了改前/改后对比
2. **`find_tools` 从来没被记进 `tools.jsonl`** —— 一天 12,250 次 `tool_call` 里 `find_tools` 一次都没有（`names.has('find_tools') === false`）
   → **没有它，关于展开成本的判断只能靠猜。补这个埋点本身值得做（未做）。**

## 七、★★ 世界证据：判断力确认恢复

`rdd_submit` 派了一个**只能靠备选工具完成**的任务（`lookup_recipe` 和 `craft` 都不在那 11 个常驻工具里，只能从目录里挑出来再展开）：

```
goal / primary_goal = "Craft a stone pickaxe."
subtask            = "Look up the crafting recipe for a stone pickaxe with lookup_recipe, then craft it with craft. Report what you found."
asset_key = "minecraft:stone_pickaxe"   minimum = 1   mode = acquire   companion = rdd
```
> ⚠️ `rdd_submit` **必填 6 个**：`goal / primary_goal / subtask / asset_key / minimum / companion`（`additionalProperties:false`），少一个就 `success:false` 报「requires goal, primary_goal, subtask, asset_key and non-negative minimum」。

模型实际动作（`latest.log`）：
```
13:10:58  chat done 7024ms tokens=9820/1800   finish=tool_calls  tool_calls=[find_tools]
13:10:58  dispatch find_tools args={"query":"select:lookup_r..."}    ← 一次只展开 1 个
13:11:01  chat done 2681ms tokens=13140/429   tool_calls=[lookup_recipe] → success
13:11:06  chat done 5038ms tokens=13840/1257  tool_calls=[interact_at]
13:11:12  chat done 6145ms tokens=15162/1285  tool_calls=[inspect_gui]
13:11:19  chat done 6597ms tokens=16994/1407  tool_calls=[transfer]
```

**⇒ 从目录里精准挑中 `lookup_recipe`、一次只展开 1 个**（回退前同一批日志里出现过「一次 `select:` 24 个工具」的请求）。
**这是「AI 看懂了目录」的正面证据，不是 BUILD_OK。**

同伴状态：`RDD` entity_id=15，(-890.5, 10, -833.5)，savanna，hp 20/20，主手 water_bucket，背包 26/41 格已用。

## 八、局限（不掩盖）

1. **只验了一个会话、一种模型**（deepseek-v4-flash）。换模型后目录摘要的判别要求可能不同。
2. **est tok 是自估**：`llm_request` 无 `promptTokens` 字段、`llm_response` 无 `usage`，绝对值不可信，只有比例可用。
3. **4 个 `RddV32DirectivesTest` 至今没跑过**（`run-mutation.ps1` 不跑 test）。刀 ⑤ 动过 `RddV32Directives` 但没跑它的测试。
4. **刀 ② 的因果是「强推断 + 世界证据」，不是受控实验**：改前的 `find_tools` 请求记录已被轮转清掉，且 `find_tools` 压根没进 `tools.jsonl`，做不了 A/B。
5. **候选 3 的代码还在 jar 里**（`ToolDisclosure.slimExpanded` + `EntityAgentLoop.slimStaleExpansions`），245 条里只命中 3 次（1.2%），无害但也无用。备份 `.pre-slimtooldef-20261002.bak` 可撤。**本轮没撤。**
6. **刀 ⑤（`harnessHints` 11→7）暂不动**，但它同样是「按关键词筛掉内容」的一刀，**风险等级介于②和①之间**（因为是用户自己写的笔记，不是原作者的）。未验证。
7. 刀 ④ 恢复了「列出全部 27 种背包物品」，**省 token 的部分（排序+短导语）保留了** —— 没有单独量过这部分省了多少。

## 九、★ 固化为红线（已写进 `30-主要功能不回退清单.md`）

> **不得为省 token 截断原作者为让模型「用得对」而写的 description / schema / 工具目录摘要。**
