## 五、教训（记经验库的那一条）
**切分支会让"另一个分支上的已完成工作"静默消失**，而日志里只留一行 `checkout`。
09-27 那次切分支时，测试日志写的是「与依赖门删除一起**未 commit**」——
**未 commit 的工作 + 切分支 = 等于删掉**。以后：
- 切分支前先 `git status` 看有没有未提交
- 跨分支搬运**逐项核对**（`git cherry` 比 `git log` 靠谱：它能识别补丁等价的 cherry-pick）
- 重要工作落盘即 commit，别攒在工作区
