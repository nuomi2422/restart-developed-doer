# 03 · 协作流程规范（O / W / C 说话流程）

## 一、角色

- **O** = OpenCode 免费 AI（写码/执行/测试/进游戏/巡检）。
- **W** = 网页免费模型 **GLM / Kimi / Qwen**（playwright 直驱，研究/方案/审核）。
- **C** = Codex `gpt-5.6-terra`（MCP，高级审核/难题升级）；**慢，可不用**。

## 二、给 W 说话的流程（一级循环）

```
用户给模块意图
 → O 生成工程文档（02-req-draft）
 → W：GLM/Kimi(/Qwen) 各问一遍（askall，联网搜资料）
 → 汇总三家给 GLM 综合（synth）
 → O ↔ GLM 对话 1~3 轮
 → 形成 06-req-final（含自问四问）
 → O 写码 → 单测 → 交 W 审核 → 补改
 → 进 MC test 实机验证 → 报告回 O → 下一轮
```

命令：`node w-brain-drive.js ask <glm|kimi|qwen> "..."` / `askall "..."` / `synth "..."`

## 三、两种说话方式（关键）

| 场景 | 谁说话 | 怎么做 |
|---|---|---|
| **用户在场** | **用户手动粘贴**给其他模型 | 用户复制内容 → 粘到网页模型 → 把回复粘回 |
| **用户不在场** | **O 自动轮回** | O 用 `w-brain-drive.js` 自动 `askall/synth`，轮回着跟网站上 AI 说话 |

> 默认：能自动就自动；用户想更精准时改手动粘贴。

## 四、W 平台取舍

| 平台 | 用不用 | 原因 |

## 六、C 层（按需）

- 每 3~4 轮/区，把「要求/架构/代码/验证/遗留」交 C 深审（`codex_ask`/`codex_review`）。
- **实测慢**（中转 API + 沙箱预置）；不用不阻塞主循环。

## 七、纪律

- W/C 回答**当参考不当真理**；函数名/API 必对真实源码核。
- 免费 AI 不得向 MC/MCP 投危险执行指令（定向豁免仅限数字1 通关/验证任务）。
- 每轮写测试日志 + `09-更新日志.md`。
