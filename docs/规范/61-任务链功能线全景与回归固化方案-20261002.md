## 一 · 总功能线：一条链，14 段

### 1.1 全景（规划段一次性 → 运行段每 tick）

```
【规划段 · AI 侧 · 一次目标一次】
S1  /goal ──► RddPlugin.beginPlanning
S2  资产口径统一入口 ──► RddPlugin.planningAssets(uuid)
        └─ 先同步 countInventory 再出快照（修「首次 /goal 时 lastInventory 为空」）
        └─ 加 villageContext（已观测村庄，只事实不含策略）
S3  ★M1★ 一级规划 ──► RddStagePlanner.planStages
        prompt = planningAssets + villageContext
                 + RddPlanningPolicy（约束块：风险/预算/optional 策略）
                 + RddPlanningKnowledge（经验知识注入，受 4 条 / 1200 字预算）
        产出 List<StageSpec>（上限 MAX_STAGES=12）
S4  ★M2★ 懒展开（不在 S3 做）──► RddDecomposer.decomposeSpecsWithHint(stage_b) → decompose(fallback)
        产出 List<SubtaskSpec>（上限 MAX_SUBTASKS=8，condition 强制非空）
        parseOne 逐条校验：不合法 → 整条 return null 丢弃
S5  RddPlanGuard ──► 剔未要求的可选工程阶段 + 剔已持有资产（全剔光 → 安全降级为空表）

        validateCondition 拒死条件（未知 mode 抛 / minimum 非有限非负抛 / 未知 type 抛）

【运行段 · 宿主侧 · 每 20 tick 一次 = 1 次/秒】
S7  ★M2★ 边界展开（真正展开在这里）──► RddDetector PENDING/WAITING 分支
        RddGoalDriver.needExpansion 报边界 → RddExpansionPolicy（预算 3 次 / 冷却 5000ms）
        → RddDecomposer 分解 → RddChainFactory.fromSpec → replaceCurrentSubtasks
        → activateCurrentFromSnapshot（依赖门 rdd.dependencyGate，生产默认关）

        ├─ Map / AssetRegistry / PlanningAssetSnapshot 三个出口
        ├─ 每个出口都 captureAcquireBaseline（幂等，已有不覆盖）
        └─ ★★ 必须 startCurrentWithCounts(counts) —— startCurrent() 不拍基线 = RL-22 事故根因

        ├─ type != inventory → WorldFactConditions.valid && RddWorldFacts.matches（必须服务端线程）
        └─ inventory ──► HardCodedEvaluator.matches
                ├─ asset_key + minimum        （hold: 现状 >= minimum；acquire: 净增 >= minimum）
                ├─ group(food|wood|blocks)    （InventoryGroups 硬编码白名单）
                └─ mode=acquire 且 baseline==null → 恒 false（不许降级成 hold）
        └─ 兜底 foodEquivalentSatisfied + 埋点 detectAssetMismatch
S11 ★M4★ 打勾 ──► completeSubtask
        surplus.hold 否决 → rt.applyHardCoded(id,true) → COMPLETED + advanceOrAwait
        → 清 body / retries / stallWatcher / gapParked / parkedWatcher / furnaceWatch
        → publish subtask_completed（evidenceSource: server_world_fact | server_inventory）
        → recordSubtaskFact（辅助留档，不用于恢复）
        → 若此时 primaryStatus == AWAITING_SUPERVISOR：
              简化 CONFIRM → ★★ recordStageFact → CompletedFactStore.recordStage → RddFactStore.save
S12 ★M5★ 下一级 ──► CONFIRM → applySupervisorDecision 推下一未满足一级 或 goal COMPLETED
        建链时 new TaskChain(goal, facts(companionId).satisfiedStageKeys(goal))
        → 命中的一级直接跳过（跨重绑 / 跨重启继承，防已达成阶段被重跑）

【上行段 · AI → 宿主】
S13 工具面 ──► rdd_status / rdd_submit / rdd_skip_optional / report_task_concern / rdd_assets / rdd_standby
        report_task_concern ──► RddNegotiationInbox.PENDING（每同伴只留一条）
        ──► 下一 tick tickNegotiation 消费 ──► REJECT/COUNTER → 重规划；PAUSE → PAUSED
              taskId 与当前二级不符 → 丢弃并 publish negotiation_discarded

【旁路段 · 与主链并行，不在 M1–M5 里但会被改坏】

        （snapshot 每二级已输出 status / skipReason / pauseReason / detectionMode / condition）
```

### 1.2 `tickRuntime` 的顺序就是契约（S9 展开）

```
countInventory
→ 死亡支线收尾（deathDropsBackInInventory → onRepairSuccess）
→ 背包满提醒 → surplus.inspect → cacheInventory → recordHistoryCurrent
→ 节流 populateAssets（每 5 次）+ RddWorldAssetObserver.observe（每 30 次）
→ tickNegotiation            ← 协商早于任何判定
→ 监督态早退 AWAITING_SUPERVISOR / REPLANNING / COMPLETED / FAILED
     （REPLANNING|FAILED 走 tryAcceptSatisfiedWhileParked + parkedWatcher）
→ RECOVERING → publish + resumeFromRecovering
→ PENDING / WAITING（未展开 → 报边界，绝不自己展开；riskGateAllows；activateCurrentFromSnapshot）
→ primaryStatus != ACTIVE → return
→ PENDING → rt.startCurrent()
→ PAUSED   → handlePaused        → return      （含 ownerPause 永不过期）
→ STALLED  → stallWatcher.handleStalled → return
→ FAILED   → 条件已满足则 early_achievement + retrySubtask + startCurrent + completeSubtask
             否则 handleSubtaskFailure（可跳过 / 停车 / 重试）
→ EarlyAchievement 连跳循环 :438-479（两处 detectionMode != HARD_CODED → break）
→ ★ :485-487  if (current.detectionMode() != HARD_CODED) return; ★
→ stallWatcher.track → RddBodyDispatcher.maybeSubmit
→ conditionMatches → completeSubtask → maybeRetryOrFail
→ catch RuntimeException 不拖垮 tick
→ finally assetTick==0 → publishTaskSnapshot("periodic_observation")
```

> **改这一段的顺序 = 改 M3。** 任何「先判后协」或「先协后判」的调整都可能改变协商被消费的时刻。
