# 15 · 收尾检测（防写新丢旧）与 进游戏失败处理

> 用户 2026-09-27 新增两条硬要求。

## 一、后置检测（防「写新丢旧」/ 防破坏既有）

**触发**：每次改动收尾 + 每轮闭环结束（不是只在开工）。**必查两项**：
1. **工程规范遵守**：对照 `01-工程规范.md`（九步流 + 回归 + 门禁）。
2. **未遗失 / 未破坏既有**：对照「不回退清单（大链路 + RL-1..8）」+「既有资产」（`_原档-自编译系统/`、`_快照-自变异系统v3/`、原位 ①②③）——
   **新写的东西不能把旧的东西挤掉 / 删掉 / 弱化。**
3. **数据清理**（2026-09-28 加）：跑 `cleanup-logs.ps1`（默认只报告，`-Apply` 才删），防日志/轮转"越积越杂"（见 `16`）。

**判据（怎么算"丢旧/破坏"）**：
- 既有文档 / 脚本 / 红线**不再存在**，或**被弱化**（少了关键约束）；
- **新内容覆盖了旧真源**（旧真源未被保留）；
- 索引指向的东西**找不到**（断链）。

**出错怎么办**：立即找回（从 `_原档-自编译系统/` / `_快照-自变异系统v3/` / 原位置 / git tag），并在 `09-更新日志.md` 记录。

> 教训来源：本次「自编译被写分裂、索引断」正是"写新丢旧"的典型。此检测就是防它复发。

## 二、进游戏验证失败处理（剧本不符合）

**规则**：进游戏跑剧本，若**剧本不符合**（世界结果 ≠ 预期）——

1. **先找原因**（查 `monitor/*.jsonl`、`latest.log`、复现）。
2. **给提示**：明确说一句「**找到原因了，剧本不对**」（用户可见）。
3. **退游戏**（**不空开**，省电 / 省 token / 防空转）。
4. **再写代码**（改完再一条龙重启验证）。

**铁律**：验证失败时**不得让游戏空转**；**先退游戏，再改码**。

> 配套：`04-进游戏巡检规范.md`（在线巡检）、`12-进游戏验证工具集.md`（启停）、skill `special-mode-loop`。
