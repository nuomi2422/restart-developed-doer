## 1. 这是什么

**自变异系统 = 让 AI 改自己代码的受控闭环**：AI 发现能力缺口 → 在隔离工作区生成候选工具 →
安全编译 → 在 `test` 实例实测（MCP 游玩 + 监测台观测 + 世界事实对撞）→ 通过门禁才晋级到 `gpt` 基线。
「自编译/自变异」在本项目同义，英文代号 **selfcompile / Numen selfcompile**。

主体是**外挂式 AI 编程工具**（不进入 Numen 游戏仓库），通过「启动/关闭游戏 + MCP 实际游玩验证 + 部署 jar」扩展能力。

三处入口：
1. **游戏内** AI 调 `selfcompile_request(requirement)` → 建可审计工作区（插件内执行/生成默认禁用）。
2. **外部脚本闭环** `new-mutation → gen-code → build-jar → deploy → verify`（`run-mutation.ps1` 串联，`run-mutation-loop.ps1` 止损重试）。
3. **看门狗** `every-10min-drive.ps1` 每 600s 读队列、投任务、nudge opencode。

## 3. 三档任务模型（速查）

| 档位 | 范围 | 审批 |
|---|---|---|
| 一档 工具级 | 单工具/局部脚本/文档修正 | 免费 AI 自主，测试+日志即可 |
| 二档 模块级(Bounded) | 心跳/看门狗/双实例/Bridge/自编译子模块 | 外脑参议 + 交叉审 |
| 三档 架构级 | RDD 核心架构/跨模块契约/生产安全模型 | 完整九步流 + **人工批准** |

发现隐藏复杂度只能升档，不能降档。高风险留人工待批。

## 4. 硬门禁（不可绕过）

- **编译成功 ≠ 行为成功**；**MCP 返回成功 ≠ 世界真变**（必须监测台 + 世界快照对撞）。
- 候选能力必须按顺序过 Promotion Gate 才能进 `gpt`，**进生产仍需人工批准**。
- 未 VERIFIED 不部署生产；部署生产前先 commit。
- 绝不直接替换生产 jar：一切变更走 `workspace → 编译 → 验证 → 部署` 显式流水线。
- 偏离方向连续两次失败找不到根因 → 止损汇报，不无限硬磕。
