# 九步流与软件工程规范

> 来源：AGENTS.md 与 `自编译系统/engineering-standards/README.md`。每个任务开工前对照，收工后逐条勾。

## 九步流（内置八规范）

1. **先分类**：工具级 / 模块级(Bounded) / 架构级(Architectural)。起步第一行自报路径，写码前停下等批准。
2. **改接口先查消费者**，接口变更必须契约回归。
3. **首测通过后立即补边界/异常/极端/多数据测试**。
4. **关键路径同步埋 debug**，日志要能回答入口、输入、分支、输出。
5. **编译成功 / MCP 返回 OK ≠ 真实行为成功**，必须看真实世界证据。
6. **按模块 commit + 标注**，保留单模块回滚点；连续两次失败找不到根因 → 止损汇报，不无限硬磕。
7. **固化闭环必须含测试、日志、事实证据**；没有证据不宣称完成。
8. **写完代码必须同步写解释性维护说明**（改了哪/为什么/怎么调用/依赖/注意事项/入口出口）；
   后续变更必须同步更新该说明 —— 没有解释的改动 = 未完成的改动。

## 门禁铁律

- 编译成功 ≠ 行为成功；MCP 返回成功 ≠ 世界真实改变。
- 未 VERIFIED 不部署生产；部署生产前先 commit。
- 每次变更按模块 commit，保留单模块回滚点，通过后 push。
- 偏离方向连续两次失败且找不到根因 → 止损汇报。

## 记录格式（每任务至少）

档位、目标、设计、参与模型及意见摘要、改动文件、测试命令与结果、Monitor/MC 事实证据、
未完成项、止损或下一步。交接文档必须能让下一个 AI 不靠口头上下文恢复。

## 分工链

| 档位 | 谁写 | 谁审 | 门禁 |
|---|---|---|---|
| 工具级 | 免费 AI 自主 | 测试记录必写 | 面向行为验证 |
| 模块级(Bounded) | 外脑池参议 + 免费执笔 | 外脑 + 交叉审 | 工作流文档先行 |
| 难复杂 | Codex | 多轮后 GPT 必审码 | 完整九步流 + 证据 |
| 最高难/高风险 | 留人工待批 | 人工 | 先跳过，不越权 |

## 免费模型额度不足时

429/不可用 → 换下一个 provider（多 provider 轮换；OpenRouter 免费池可作兜底，见 opencode 配置）。
