# 自编译/自变异系统（Numen selfcompile）全流程总结（2026-09-25）

> 供外部 AI 审核用的一段话总结（来源：`plugins/selfcompile/*` Java + `rdd-selfcompile/scripts/*.ps1` 真实代码）。

自编译/自变异系统（Numen selfcompile）是一套受控的“AI 改自己代码”闭环，入口有三处——①游戏内 AI 调 `selfcompile_request(requirement)`：经 `SelfCompileService.create → MutationWorkspace.create` 只创建可审计工作区并落 `manifest.json`，当前**不生成代码、执行保持禁用**（`MutationPipeline` 注释：“仅编排安全的前置阶段，执行仍禁用”）；②外部 harness 脚本链 `new-mutation.ps1 → gen-code.ps1 → build-jar.ps1 → deploy.ps1 → verify.ps1`，由 `run-mutation.ps1` 串成单条直闭环[1/6..6/6]、`run-mutation-loop.ps1` 做 ≤MaxAttempts 的止损重试；③`every-10min-drive.ps1` 看门狗每 600s 读 `selfcompile-queue.json`、把任务投成 `scripts/requests/req-*.json` 并 nudge opencode（现已附“自变异待处理”摘要）。单次 mutation 的生命周期由 `MutationStateMachine` **硬约束**：`REQUESTED → WORKSPACE_CREATED → GENERATED → STATICALLY_CHECKED → COMPILED → CANDIDATE → VERIFIED → DELIVERED`，失败走 `FAILED → ARCHIVED → 可重新 REQUESTED`，止损循环终止于 `STOP_LOSS`（`DELIVERED/STOP_LOSS` 为终态）。各步事实：**创建工作区**=在 `config/numen/selfcompile/mutations/<id>/` 建 `source/ jar/ deploy/ mcp-log/ monitor-snapshot/ requirement.txt manifest.json`；**生成**=由外部 AI 产出 NumenTool 源码，`gen-code.ps1` 落到 `plugins/selfcompile/.../generated/` 并注册 `SelfCompileEntry`，`recordGeneratedSource` 置 `GENERATED`；**安全编译**=先静态检查置 `STATICALLY_CHECKED`，再 javac 编译，成功置 `COMPILED`，失败把 `file:line:col: message` 结构化写入 `reports/errors.json` 并置 `FAILED`（供外部 AI 定位重修）；**候选**=`MutationArtifactStore` 仅允许 `COMPILED` 工件提升为 `CANDIDATE`；**验证**=`verify` 用监测台快照/日志/事件/source/classes/jar 哈希做证据校验，缺一证据即 `FAILED`、齐则 `VERIFIED`；**交付**=`deploy.ps1` 把 jar 部署到实例 `mods`（当前生产实例 mods 目录双备份）并置 `DELIVERED`。全过程受 `MutationBudget`（最大尝试次数/时长）限制，并由 `opencode-harness.ps1`（opencode CLI，模型 `opencode/big-pickle`，readonly/implement 模式 + guard）承接执行；设计上还规划了 `MutationRecord` 因果链、变更包 `Proposal` 状态机（PROPOSED→COMPILED→TESTED→VERIFIED→ACTIVE）、权限分级（Tier0 配置 / Tier1 单文件单模块 / Tier2 架构)与多 Harness 并发写锁，但多为未实装或部分实装——**核心安全边界：绝不直接替换生产 jar，一切变更走 workspace→编译→验证→部署的显式流水线，且当前执行/生成阶段在插件内默认禁用，真正改码由外部 harness + 人工/上位 AI 推动。**
