# Self-Compile 自变异主循环（主体设计）

> 方向纠正后：主体是**外挂式 AI 编程工具**，通过启动/关闭游戏 + MCP 实际游玩验证 + 部署 jar 实现能力自我扩展。本文定义这个主循环。

## 1. 循环概览

```text
        ┌──────────────────────────────────────────────┐
        ▼                                              │
[ 任务/能力缺口 ]                                      │
        │                                              │
        ▼                                              │
[ 外部 AI 分析：读代码/经验/铁律 ]                      │
        │                                              │
        ▼                                              │
[ 生成/修改原子工具源码 ]                                │
        │                                              │
        ▼                                              │
[ 安全编译门：静态检查 → javac → jar ]                  │
        │                                              │
        ▼                                              │
[ 启动实验 MC 实例（存档 gpt）]                          │
        │                                              │
        ▼                                              │
[ 通过 MCP 实际游玩/调用工具 ]                          │
        │                                              │
        ▼                                              │
[ 读监测台 events/state/tools + 世界快照对撞 ]           │
        │                                              │
        ├── 验证通过? ── 否 ──► [ 记录失败 → 归档 → 修改源码再试 ]──►┐
        │                                                           │
        │ 是                                                        │
        ▼                                                           │
[ 部署 jar 到生产 MC → 重启游戏 ]                                    │
        │                                                           │
        ▼                                                           │
[ 记录结果 + 经验 → 返回顶部 ] ◄────────────────────────────────────┘
```

## 2. 主控关系（外部优先）

```text
默认：
  外部 AI（本开发工具）自控游戏
    ├── 决定何时启动/关闭 MC
    ├── 决定生成/修改什么工具
    ├── 通过 MCP 亲自玩、亲自验
    └── 部署后重启

备用（接口保留，非主控）：
  游戏内 Numen AI 请求 request_compile
    └── 传需求 → 外部执行 → 回传结果
```

## 3. 每次循环的审计记录

每次变异保存：

```text
mutation-id
需求
源码变更
编译结果
jar 产物
游戏启动结果
MCP 操作 + 返回
监测台事件
世界快照对撞结论
验证结论（真成功/假成功/失败）
止损原因（如有）
```

## 4. 硬门禁（不可跳过）

- 编译成功 ≠ 游戏行为成功；
- MCP 返回成功 ≠ 世界状态正确；
- 必须世界快照对撞（真实铁证）才算 VERIFIED；
- 一次验证失败 ≠ 无限重试；
- 未 VERIFIED 不得部署生产；
- 生产部署前先 commit，防止不可回滚。

## 5. 双环境职责

| 实例 | 用途 | 门禁 |
|---|---|---|
| 实验 MC | 验证候选能力，允许破坏 | 可随时重建 |
| 生产 MC | 实际游玩/交付 | 只有 VERIFIED 候选才部署，部署前 commit |
