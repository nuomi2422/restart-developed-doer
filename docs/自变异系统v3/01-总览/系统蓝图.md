# 系统蓝图

> 来源：既有 `rdd架构\自编译系统\README.md`（原档见 `06-历史文档/自编译系统原档/README.md`）。

## 需求理解

把现有 RDD 自编译/自变异能力、Claude↔Codex Harness 协作、网页模型评审、10 分钟心跳、
Monitor 看门狗、`gpt`/`test` 双 MC 实例和软件工程规范整理到同一资料中枢。
本目录提供统一入口、索引、模板和实施边界。

## 目标

1. 让一个 Harness 能受控调用/通信另一个 Harness（Codex 主指挥官，Claude/OpenCode 下位）。
2. 让自编译系统在隔离实验环境生成、编译、验证、回滚候选能力，证据充分才交付。
3. 让通宵任务、监测任务和长线测试具备断线恢复能力。
4. 让每个 AI 知道任务档位、权限、交接格式、测试门禁和资料存放位置。

## 非目标

- 第一阶段不重写 DD Java 核心，不把文档目录当运行时目录。
- 不允许任一模型单独批准生产部署。
- 不要求模型输出隐藏思维链。

## 总体架构

```text
用户任务
   │
   ├─ Codex CLI（GPT-6-Astra）：主指挥官/最终技术决策
   │       ├─ claude-codex-bridge ── MCP ── Claude CLI：辅助 Harness
   │       └─ OpenCode：免费执行 Harness
   │
   ├─ 网页模型池：DeepSeek、千问、ChatGPT、Gemini（触发条件满足时）
   │       └─ 开启思考/推理模式，只返回意见
   │
   ├─ Git / 契约测试 / 回归测试 / 日志证据
   │
   └─ 自编译外部编排
          ├─ test：候选变异实验
          └─ gpt：通关 MC 与长线基准验证
```

## 心跳与任务注入

复用升级现有 `scripts\heartbeat.ps1`，不新建第二套。当前落地为 `every-10min-drive.ps1`（600s 注入「继续」）。

```text
每 10 分钟唤醒 → 读任务链/最近交接/监测日志 → 有长线任务：恢复并注入继续 → 无任务：不启动
→ 记录唤醒/恢复/停止/止损
```

## Monitor 看门狗与双实例

启动 `gpt`/`test` 后等约 2 分钟检查游戏进程、`latest.log`、Monitor `server.py`、`ws://127.0.0.1:8765`：

1. Monitor 失联：先重启 Monitor，保留游戏。
2. 游戏崩溃：记录 crash，重启实例并重连 Monitor。
3. 连续恢复失败：停止本轮，写交接/止损，不无限重启。
4. 同一时间只允许一个实例占用 8765。

实例职责固定：

- `test`：候选能力实验，允许失败和回滚；候选 JAR 不得污染 `gpt`。
- `gpt`：通关 MC、长线验证和生产基准；只接受已通过实验验证的版本。

## 部署边界

`numen_api-neoforge-1.21.1-<ver>-dev.jar`（API 引擎）与 `numen-neoforge-1.21.1-<ver>-dev.jar`（Core 工具包）
必须作为两个文件同时放入实例 `mods/`；API 不能改名覆盖 Core，缺 Core 会报 `mine` 未注册。
部署后检查 `numen-core registered 51 tool(s)`，再用真实资产和 Monitor 事件验收。
