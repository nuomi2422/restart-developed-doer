# Module Blueprint（目标边界补齐模块模式）

## 定位

本技能把「用户一句话描述 独立模块 / 总架构 / 核心目标」升级为**可执行的模块总文档**。
它不是便签：产出物必须让任何 AI 不靠口头上下文即可恢复、评审和执行。

## 触发情况

- 用户描述独立模块、总架构或核心目标，要求补齐架构细节。
- 在既有架构目录（`E:\新建文件夹\rdd架构\`）下新增/细化某个子系统的设计。

## 工作流（8 步）

1. **锁定方向**：先重述用户的总目标与架构方向，确认不管补多少细节都**不偏移**它。写进文档首段「不可偏移的架构方向」。
2. **探索现状**：读 `E:\新建文件夹\rdd架构\` 相关既有文档（README、implementation-plan、engineering-standards），列出已实装/已设计/缺口。
3. **外脑池参议**：开 DeepSeek 专家模式网页窗口（.playwright-profile），把「模块目标 + 待补齐点」发给它拿第二意见；记录意见摘要到文档（当参考不当真理，函数名必须对真实源码核）。
4. **上位协同**：在有真实架构取舍时，汇总裁决（多轮迭代直到稳定）；记录参与模型与意见摘要。
5. **免费模型执笔**：按下方模板产出总文档 md，放 `E:\新建文件夹\rdd架构\`（模块名 + 模块模式标识，如 `rdd-xxx-module.md`）。
6. **交叉审**：外脑/免费互审，或在用户在场时请用户审核心取舍。
7. **落实施边界**：写明哪些已实装（证据在哪）、哪些是设计待批准；不得把设计当运行证明。
8. **封口**：写入测试日志（档位/目标/改动/证据/下一步），依九步流留批准门。

## 产出模板

```markdown
# <模块名> 模块蓝图（Module Blueprint）

## 不可偏移的架构方向
（用户原话/总目标/架构约束，任何补充不得偏离）

## 模块边界
- 属于：/<父模块> / 独立子系统 / 总架构的一层
- 输入/输出契约：与哪些既有模块交互、接口形状
- 非目标：明确不做什么

## 目标与用户故事
（为什么需要、验收标准、贴用户原话）

## 核心设计（由外脑池 + GPT 上位补齐）
- 关键组件与数据流
- 状态机/并发/回滚边界（如有）
- 真实源码对照点（引用 `E:\restart developing doer\minecraft-numen\src` 具体文件）

## 工作流与执行分档
工具级 / 模块级(Bounded) / 架构级 各归哪些部分，谁写谁审门禁

## 测试与事实证据要求
- 边界/异常/极端/多数据测试计划
- debug 埋点说明（入口/输入/分支/输出）
- 真实世界验证物（MCP 只读观察 / MC 世界事实 / 日志）

## 交接与下一步
（下一个 AI 不看口头上下文也能恢复）
```

## 纪律

- 免费模型是执笔，不许在用户未批准前展开写代码；本技能只产出设计文档。
- 「外脑的回答」永远当参考；凡是函数名/API 名，必须先对真实源码核对再写进文档。
- 产出 md 完成后回到全局 AGENTS.md 末尾完成检查索引勾选。
