# ⑦ 世界与经济 · 接线清单（骨架 → 接数据源）

日期：2026-10-05。这两页是**骨架页**：架构里有，数据源大半没接。
本页的作用是告诉下一个接手的 AI：**每一块现在缺什么、接上之后怎么让它自动变绿**。

- 页面：`7.1 单一世界 · 环境事实`（`/api/world-facts`）与 `7.2 经济与开关`（`/api/economy`）
- 服务端：`world-facts.mjs` / `economy.mjs`
- 前端：`js/world-facts-view.js` / `js/economy-view.js`
- 测试：`node --test tests/world-economy.test.mjs`

---

## 0. 三条通用规则（改任何一页都适用）

1. **不要手改页面上的「已接入 / 未接入」文字。**
   状态是服务端**运行时探测**出来的（`WIRING[].probe`）。写死的状态一定会骗人。
2. **不要为了让页面变绿，往数据里塞占位值。**
   那就把「未接入」变成「假接入」，比不接更坏。
3. **判据必须能区分「字段缺失」与「字段是 0 / 空」。**
   `hasKey(x)` 与 `x.foo != null` 是两回事，混起来就会把「没产量」判成「产量 0」。

## 1. 7.1 单一世界 · 环境事实

### 1.1 现在读到的是真的

| 来源 | 文件 | 实测 |
|---|---|---|
| 世界事实本体 | `config/numen/rdd-assets/<uuid>.json` | 458 条（structure 173 / entity 144 / village 96 / machine 39 / base 6） |
| 任务链血缘 | `config/numen/rdd-facts/<uuid>.json` | 266 条 |
| 资产状态历史 | `config/numen/rdd-history/<uuid>.json` | 64 条，**purpose 全是 UNKNOWN** |
| 死亡台账 | `config/numen/rdd-ledger/<uuid>.json` | 21 条，多数 UNVERIFIED、evidence 空 |

★ 归属（这条事实属于哪只同伴）**来自文件名**，不是数据字段。页面已标出来，别当成数据里的事实。

### 1.2 九条接线契约（包号 → 契约项 → 判据）

| 包号 | 契约项 | 接上什么 | `probe` 现在怎么判 |
|---|---|---|---|
| N1 | 事实可信度 | `observation.value.confidence`（字符串） | `ctx.valueKeys.has('confidence')` |
| N1 | 事实覆盖范围 | `observation.value.coverage` | `ctx.valueKeys.has('coverage')` |
| N1 | 已知/未知/过期三态 | `observation.value.knowledge` | 写死 `false` |
| N1 | 三级投影 | 投影层（简要/任务相关/详细） | 写死 `false` |
| N2 | 资产用途语义 | `rdd-history` 的 `purpose` 不再是 UNKNOWN | `historyRows.some(h => h.purpose && h.purpose !== 'UNKNOWN')` |
| N2 | 死亡丢失的确认 | `rdd-ledger` 的 `state` 到终态且 `evidence` 非空 | `ledgerRows.some(l => l.verified === true)` |
| N2 | 丢失重要度累计 → 分级重规划 | 重要度 + 阈值 + 分级建议 | 写死 `false` |
| N3 | 一级目标声明需求 + 机会提前获取 | 需求清单 + 机会候选层 | 写死 `false` |
| N6 | 机器描述与设计态/运行态分离 | 机器描述对象 | 写死 `false` |

**写死 `false` 的那些**：接上之后把 `probe` 改成能看见它的判据即可，判据自己选，但必须满足规则 3。

### 1.3 已知要避开的坑

- **事实年龄用 `observation.observedAt`，不是文件 mtime。** mtime 是「这份 JSON 什么时候写的」，两者在轮转/缓存下差很远。
- **过期不当当前**：`STALE_SECONDS`（默认 6 小时）以上的单独一栏；**年龄未知单独一栏**，不许塞进「旧」。
- **「没见过」与「见过且是 0」现在分不开** —— 这就是 N1 三态那条未接入的原因，不要用「0 条」冒充「没见过」。

## 2. 7.2 经济与开关

### 2.1 现在读到的是真的

| 来源 | 文件 | 实测 |
|---|---|---|
| AC 脚本库 | `config/numen/acx/library.json` | 12 个 defs |
| 磁盘脚本 | `config/numen/acx/lib/stable/*.ac` | 11 个 stable + 6 个 `.stale-*` 旧版 |
| 落盘运行记录 | `config/numen/acx/records.jsonl` | 101 条，**SUCCESS 0 条** |
| 运行事件流 | `monitor/acx.jsonl` | 129 次运行 / 28 成功 / 101 失败 |

★ **`records.jsonl` 只落 PAUSED / FAIL / TIMEOUT**。所以「落盘里没有成功记录」**不是**「没有成功运行」。
成功率只能从 `monitor/acx.jsonl` 的 `RUN_FINISHED` 算，两个来源**不可相加**。

### 2.2 九条接线契约

| 包号 | 契约项 | 接上什么 | 判据 |
|---|---|---|---|
| 72 | 产量字段（AcxProgress 11 个） | `records.jsonl` 的 `progress` 里出现那 11 个键 | `ctx.progressKeysSeen > 0` |
| 72 | 72 号八个经营脚本 | 八个脚本进 acx 库 | `ctx.rosterFound.length > 0` |
| N5 | 经济配置文件 | `config/numen/` 下候选文件名之一 | `ctx.configFound` |
| N5 | 模块启用开关 | 配置里有 `modules` / `moduleEnabled` | `hasKey(ctx, 'modules', 'moduleEnabled')` |
| N5 | 经验条目禁用 / 注入上限 | `injection` / `experienceInjection` / `injectLimit` | `hasKey(...)` |
| N5 | 目标禁用清单 | `deniedGoals` / `goalDenylist` / `blockedGoals` | `hasKey(...)` |
| N5 | 配置版本与坏配置回退 | 配置有 `version` | `configFound && configHasVersion` |
| N5 | 热切换 | 运行中换配置生效 | 写死 `false` |
| 73 | `records.jsonl` 记 SUCCESS | 落盘覆盖 SUCCESS | `ctx.recordsSuccess > 0` |

**经济配置候选文件名**（页面会把试过的都列出来）：
`economy.json` / `economy-config.json` / `rdd-economy.json` / `injection.json` / `policy.json` / `module-toggles.json`
—— 放到其中任一个都行；找不到时页面**不显示任何默认值**。

### 2.3 72 号八个经营脚本（现状：8 个全未实现）

| 顺序 | 脚本 | 机制假设 | 已知阻塞 |
|---|---|---|---|

### 2.4 已知要避开的坑

- **`records.jsonl` 不记 SUCCESS** ⇒ 「成功率」只有一个来源。
- **脚本在 `library.json` 里有定义 ≠ 它是可自动批准的 stable 脚本。** 72 号明确：未实机验收的不得放 stable 路径。
- **11 个产量字段一个都没有真实读数**（`progress` 恒为 `{}`）⇒ 页面**不画产量曲线**。画一条贴着 0 的线就是拿 0 冒充「没有产量」。
- **经济配置读不到时不许显示默认值。** 编一个「模块默认全开」出来就是在骗人，而这一页存在的意义就是不骗人。

**页面验收标准（人眼）**：

1. 接上某一条之后，那一行从「未接入」变成「已接入」，顶部「已接入 X / Y」跟着涨。
2. 没接的仍然是「未接入」，**没有变成 0**，也没有变成空白。
3. 页面里搜不到 `undefined` / `NaN` / `**`（架构文档的强调必须渲染成粗体而不是漏星号）。
